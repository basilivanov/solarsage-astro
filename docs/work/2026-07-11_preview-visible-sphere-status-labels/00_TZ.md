# ТЗ — видимые статусы в навигаторе 12 сфер

Дата: 2026-07-11
Ветка: `preview/solarsage-v2-human-first-navigator-ux`
Режим: локальный preview на `3003`, без commit/push/merge.

## Цель

На preview URL:

```text
http://127.0.0.1:3003/day/2026-07-08?fixture=three-horizon-timing&why=1
```

пользователь должен понимать смысл каждой из 12 сфер не только по цветной
точке. Статус необходимо написать словами:

- поддерживающий;
- нейтральный;
- требующий внимания;
- высокая степень напряжения, когда действие лучше отложить.

Не делать fixture-only CSS/markup hack. Изменить обычный product component
навигатора так, чтобы решение можно было затем перенести в main без переделки.
Fixture нужен только как стабильный preview payload.

## Каноническая семантика

Backend contract уже содержит четыре verdict enum. Сохранить их без изменения:

| Backend verdict | Короткий текст на плитке | Полный текст в раскрытом блоке | Цветовая семья |
|---|---|---|---|
| `good` | `Поддержка` | `Поддерживающий фон` | emerald/зелёный |
| `neutral` | `Ровно` | `Нейтральный фон` | violet/фиолетовый |
| `caution` | `Внимание` | `Требует внимания` | amber/жёлтый |
| `avoid` | `Отложить` | `Высокое напряжение · лучше отложить` | rose/красный |

Концептуально это три семейства: поддержка, нейтральный фон, напряжение.
`caution` и `avoid` — две степени напряжения, поэтому технически сохраняются
четыре action states.

Не использовать в UI raw enum `good/caution/avoid/neutral`.

## 1. Компактные плитки 12 сфер

Текущая цветная точка остаётся, но больше не является единственным носителем
смысла.

В каждой кнопке `data-testid="concrete-day-advice-row"` показать под названием
сферы короткий статус из таблицы:

```text
Работа
Внимание

Спорт
Поддержка

Здоровье
Ровно

Покупки
Отложить
```

Требования:

1. Статус видим обычному пользователю, а не только через `sr-only`.
2. Добавить стабильный selector:

   ```text
   data-testid="concrete-day-advice-row-status"
   ```

3. На status element указать нормализованный:

   ```text
   data-status="good|neutral|caution|avoid"
   ```

4. На самой row button оставить `data-status`, но выставлять нормализованное
   значение с fallback `neutral`, а не потенциально неизвестную строку.
5. Текст статуса должен иметь цвет своей semantic family, но оставаться
   читаемым по контрасту в light/dark theme.
6. Не уменьшать tap target ниже текущего размера. Допустимо немного увеличить
   `min-height`, если две строки не помещаются.
7. Название сферы и статус не должны обрезаться на viewport `390px`.
8. Существующие icon, dot, chevron, `aria-expanded`, `aria-controls`, focus ring и
   controlled selection сохранить.
9. Удалить/не дублировать прежний `sr-only` status copy, если видимый status уже
   входит в accessible name. Screen reader не должен дважды читать один статус.

## 2. Раскрытый блок сферы

В `SphereDetails` рядом с заголовком либо непосредственно под ним показать badge
с полным статусом.

Для fixture-сферы `Работа и статус` ожидается:

```text
Работа и статус
Требует внимания

Что может проявиться
В этой сфере сегодня особенно важны точность и отсутствие спешки.

Что поможет
Не форсируйте разговор о статусе — сначала отделите принципиальное от реакции на давление
```

Требования:

1. Badge расположен до секции `Что может проявиться`.
2. Добавить selector:

   ```text
   data-testid="concrete-day-advice-details-status"
   ```

3. Badge и details root получают нормализованный `data-status`.
4. Цвет badge соответствует той же semantic family, что icon/dot/status плитки.
5. Полный visible copy строго из таблицы выше.
6. Не менять тексты `Что может проявиться`, `Что поможет`, personal-map note,
   `Почему это именно про меня`, `Свернуть` в рамках этой задачи.
7. Не показывать пользователю confidence, raw astrology evidence, техники, орбы
   или backend enum.

## 3. Архитектура

1. Не создавать две независимые mapping tables для compact и details.
2. Расширить одну каноническую presentation metadata map для verdict:
   - normalized enum;
   - compact visible copy;
   - details visible copy;
   - dot/icon/status/badge color classes.
3. Если metadata остаётся локальной в `concrete-day-advice.tsx`, назвать её так,
   чтобы было понятно, что она является UI presentation map. Не переносить это
   в API/backend.
4. Unknown verdict безопасно нормализуется в `neutral` и показывает `Ровно` /
   `Нейтральный фон`.
5. API, contracts, auth, fixture endpoint, V2 timing, Why и production services
   не менять.
6. Сохранить GRACE module contract/map; обновить inputs/outputs/invariants для
   visible semantic status и public DOM contract.

## 4. Тесты

Добавить focused component coverage.

Минимальные assertions:

1. Compact rows отображают точные пары:
   - `good` → `Поддержка`;
   - `neutral` → `Ровно`;
   - `caution` → `Внимание`;
   - `avoid` → `Отложить`.
2. После раскрытия соответствующей сферы details badge отображает:
   - `Поддерживающий фон`;
   - `Нейтральный фон`;
   - `Требует внимания`;
   - `Высокое напряжение · лучше отложить`.
3. `data-status` на row/status/details совпадает с нормализованным enum.
4. Unknown verdict fallback проверять только если это можно сделать без обхода
   TypeScript contract; иначе достаточно unit test чистого normalizer/helper.
5. Accessibility disclosure contract (`aria-expanded`, `aria-controls`) не
   регрессировал.

Использовать structural selectors, а не CSS class как основную опору теста.
