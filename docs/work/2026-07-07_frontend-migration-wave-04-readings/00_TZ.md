- Do not import `lib/mocks/*`, `lib/demo-data.ts`, or any mock-preview file from product runtime paths.

## 5. In Scope

### 5.1 `/readings` overview presentation

Bring `/readings` closer to the committed mock-preview visual oracle:

- first viewport should match `docs/superpowers/specs/assets/2026-07-07-mock-preview/readings.png` in composition, spacing, hierarchy, and mobile fit;
- header should use the same quiet label + serif heading pattern as the oracle;
- info banner should remain short and calm;
- available cards should visually match the oracle's density, icon pill, title/description/teaser/CTA hierarchy;
- available order should remain `Хорар`, then `Натальная карта`;
- bottom tab bar should remain the existing shared `TabBar`; do not fork it for this wave;
- coming/in-development formats may stay below the first viewport, but must be visibly unavailable and cannot pretend to be working products.

Text does not have to match the mock screenshot byte-for-byte. Visual hierarchy and product-safe behavior matter more than exact copy.

### 5.2 Navigation and behavior

Required:

- clicking the horary available card navigates to `/readings/horary`;
- clicking the natal available card navigates to `/readings/natal`;
- unavailable/coming cards do not navigate to nonexistent working flows;
- unavailable/coming cards either open `InDevOverlay` or are disabled with a clear accessible state;
- `InDevOverlay` remains dismissible through its close affordances;
- no horizontal overflow on a `390x844` mobile viewport.

### 5.3 UI Semantic/Test Contract

Expose stable selectors and accessibility states:

- `data-testid="readings-screen"` on the root;
- root `data-state="ready"` for the catalog screen;
- `data-testid="readings-header"`;
- `data-testid="readings-info-banner"`;
- `data-testid="readings-available-section"`;
- `data-testid="readings-available-list"`;
- `data-testid="readings-card-horary"`;
- `data-testid="readings-card-natal"`;
- each available card must expose its target as `data-href="/readings/horary"` or `data-href="/readings/natal"`;
- `data-testid="readings-coming-section"` when coming formats render;
- `data-testid="readings-coming-list"` when coming formats render;
- coming cards use `data-testid="readings-card-<key>"` and `data-state="disabled"` or `aria-disabled="true"` if they are not actionable navigation;
- `data-testid="readings-in-dev-overlay"` on the in-development dialog when open;
- modal/sheet uses `role="dialog"` and `aria-modal="true"`;
- close buttons have accessible names;
- icon-only buttons have `aria-label`;
- if a card is implemented as a `<button>`, it must have a clear accessible name from visible title text;
- if a card is implemented as a `<Link>`, use real `href` and an accessible link name.

Tests must not depend on Tailwind class names.
