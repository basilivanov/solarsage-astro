# Corpus benchmark: 5 синтетических карт × 30 дней × 3 режима (диагностика, не фриз)

Дата прогона: 2026-07-29. Сайдкар: фиксированный (геометрическая секта), standalone на `127.0.0.1:18099` (продовый 18091 не трогали). Раннер: `analysis/corpus_runner.py` (HTTP-клиент на воркер, чекпоинты chart-day, шардирование `index % workers`).

## 1. Конфигурация

- Карты (из `corpus_manifest.v1.json`): `syn-005-murmansk` (high-lat 68.97°N, Europe/Moscow, evening), `syn-045-sao_paulo` (−23.55°, America/Sao_Paulo, night), `syn-040-quito` (экватор, America/Guayaquil, day), `syn-000-moscow` (mid, Europe/Moscow, day), `syn-020-london` (mid, Europe/London, day).
- Диапазон: 2026-07-01..2026-07-30 (30 дней). Режимы: exact, bucket, unknown. Итого 450 chart-day (по 150 на режим).
- Работа на chart-day: 1+3+7 = 11 вызовов `/v1/activation-layer` (по контрольным временам режима) + `/v1/natal` по временам (кэш на карту) + `/v1/transits` (кэш на день/tz, общий между картами) + локальные normalize_day/DayDelta/ledger/классификация (fixed model v1.5 + hero rules T1 + canonical margin + гео-секта).

## 2. Результаты производительности

| метрика | w=1 | w=2 | w=4 |
|---|---|---|---|
| wall time | 254.9с | 249.7с | 262.6с |
| sidecar CPU (utime+stime) | 239.6с | 245.2с | 255.0с |
| sidecar загрузка (ядер) | 0.94 | 0.98 | 0.97 |
| scaling efficiency | 1.00 (base) | 0.51 | 0.24 |
| ошибок (chart-day) | 0 | 0 | 0 |

Стоимость chart-day (по чекпоинтам, w=1): **mean 0.561с, медиана 0.451с, p90 1.103с, max 1.446с**.

**Вывод по масштабированию: ускорения от воркеров нет** — однопроцессный uvicorn-сайдкар насыщает ~1 ядро уже при одном клиенте. Узкое место — CPU сайдкара (эфемериды + построение слоя активаций), а не клиентский пайплайн. Для корпуса нужны **реплики сайдкара за раннером** (несколько портов, round-robin/shard по сайдкар-URL на воркер), а не больше клиентских воркеров на один инстанс.

## 4. Диагностические частоты (w=1, 5 карт × 30 дней)

| режим | hero rate | med significant | med public | med time_sensitive | tense share |
|---|---|---|---|---|---|
| exact | 0.000 | 15.0 | 40.5 | 0.0 | 1.00 |
| bucket | 0.000 | 13.0 | 13.0 | 49.0 | 1.00 |
| unknown | 0.000 | 12.0 | 12.0 | 82.0 | 1.00 |

- **0 hero-дней из 450** (150 на режим): на этих 5 синтетических картах за июль 2026 hero-событий нет — при 10–12% на карте владельца это маловыборочное наблюдение (30 дней, 5 карт), а не противоречие; финальные частоты покажет полный корпус.
- tense share = 1.0 везде (как у владельца: каждый день есть значимый tense-юнит) — подтверждает, что «tense-день» нужно определять на уровне якорей/hero, а не всех значимых юнитов.
- bucket/unknown отсекают ~49/~82 факта на день как time_sensitive (публичность 13/12 против 40.5 у exact).

## 5. Дизайн раннера (corpus_runner.py)

- Чекпоинт на chart-day: `run_dir/checkpoints/{chart_id}/{mode}/{date}.json`, атомарная запись (tmp+rename); kill теряет максимум текущий chart-day; resume пропускает ok-чекпоинты (проверено: повторный прогон — 4/4 skipped).
- Шардирование: детерминированно `index % workers`; `--shards/--shard` для многохостового запуска.
- Воркер = процесс (multiprocessing.Pool), один keep-alive httpx-клиент на воркер; кэши natal (chart+time), transits (date+tz), signals (chart-time, date).
- Сбои: `run_dir/failures.jsonl` (по одной строке на chart-day с типом ошибки); error-чекпоинт перезапускается при resume.
- Агрегация (`aggregate.json` / subcommand `aggregate`): state distribution по режимам, hero rate, медианы/p90 значимых импульсов и публичных фактов, tense-серии только по выбранным (публичным значимым) юнитам (max/медиана по картам), распределение hero-сфер, латентности по типам вызовов.
- Дубль-проверка: в каталоге уже есть параллельная разработка `corpus_replay.py` (+ `direct_replay_pipeline.py`, `aggregate_corpus_shards.py`, `birthtime_replay.py`, тесты) — in-process раннер без HTTP. `corpus_runner.py` написан по требованию ТЗ (per-worker HTTP sidecar client, chart-day чекпоинты); перед фризом выбрать один путь (HTTP-раннер честнее меряет сайдкар как сервис; in-process быстрее за счёт отсутствия HTTP-слоя).
