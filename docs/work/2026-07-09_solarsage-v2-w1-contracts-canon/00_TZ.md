## Goal

Implement only Wave W1 from `docs/15_SolarSage_v2_activation_audit_TZ.md`.

W1 prepares typed contracts, canon loading/validation, and version metadata for SolarSage V2. It must not enable V2 scoring behavior, must not generate fake activations in TodayPayload, and must not alter current scoring results.

## Architectural Rules

1. No V2 scoring behavior in this wave.
   - Do not change `ScoringService.score_day()` math.
   - Do not apply activation bonuses or convergence changes.
   - `make audit-day ... DATE=2026-07-08` must remain deterministic.

2. Do not lie in runtime metadata.
   - Do not set production `TodayPayload.meta.scoring_version` to `ss-scoring-2.0` until V2 scoring is actually used.
   - Do not set production `activation_layer_version` to `al-1.0` until an activation layer is actually built in W2.
   - The contracts may support V2 string versions now, but runtime values must describe the active implementation.

3. Preserve existing public wire compatibility where possible.
   - If an existing meta field changes type, use a backward-compatible union such as `int | str`.
   - Add new optional fields rather than removing existing fields.
   - Regenerate OpenAPI/TS contracts and commit generated outputs.

4. Avoid name collisions.
   - `apps/api/app/schemas/today.py` already has a legacy `ActivationEvidence` for convergence UI.
   - New canonical activation schemas must live in `apps/api/app/schemas/activation.py`.
   - If re-exporting through `app.schemas`, use explicit names and avoid breaking existing `TodayPayload.activation_evidence`.

5. Canon files must not be dead data.
   - `activation_rules.v1.yml` and `scoring_v2.v1.yml` must be loaded and validated by production API startup/import path.
   - Invalid canon must fail loudly in dev/test.
   - The loader may be used by existing scoring for v1 canon files, but must not change scoring semantics.

### 1. API activation schemas

Create:

```text
apps/api/app/schemas/activation.py
```

Use `CamelModel` for API schemas so aliases remain consistent with the rest of the API contracts.

Implement at minimum:

```python
ActivationTargetType = Literal["planet", "house", "lot", "angle", "sphere"]
ActivationPolarity = Literal["supportive", "tense", "mixed", "neutral"]
ActivationPhase = Literal["applying", "exact", "separating", "background", "period"]
```

```python
class ActivationEvidence(CamelModel):
    id: str
    technique: str
    technique_family: str
    target_type: ActivationTargetType
    target_key: str
    kind: str
    active: bool = True
    source_planet: str | None = None
    source_frame: str | None = None
    target_planet: str | None = None
    target_frame: str | None = None
    aspect: str | None = None
    orb: float | None = None
    applying: bool | None = None
    exact_at: str | None = None
    phase: ActivationPhase = "background"
    house: int | None = None
    lot: str | None = None
    angle: str | None = None
    strength: float = Field(ge=0.0, le=1.0)
    polarity: ActivationPolarity = "neutral"
    weight_hint: float | None = None
    evidence: str
    debug: dict[str, Any] = Field(default_factory=dict)
```

```python
class ActivationLayer(CamelModel):
    schema_version: str = "activation-layer.v1"
    activation_layer_version: str = "al-1.0"
    calculation_version: str
    target_date: str
    target_time: str
    target_tz: str
    house_system: str
    activations: list[ActivationEvidence]
    by_planet: dict[str, list[str]]
    by_house: dict[str, list[str]]
    by_lot: dict[str, list[str]]
    by_angle: dict[str, list[str]]
    warnings: list[str] = Field(default_factory=list)
```

Invariants to test:

- `strength < 0` and `strength > 1` are rejected.
- `by_planet`, `by_house`, `by_lot`, `by_angle` store activation ids, not embedded activation objects.
- every id referenced by index maps exists in `activations`.
- `evidence` is required.
