## 5. In Scope

### 5.1 `/readings/horary` presentation

Bring `/readings/horary` closer to `docs/superpowers/specs/assets/2026-07-07-mock-preview/readings-horary.png`:

- header/back link remains compact and safe-area aware;
- title block matches oracle hierarchy and spacing;
- quota card matches oracle density and remains backed by `HoraryQuotaRead`;
- category chips and form controls fit mobile without overflow;
- question textarea remains usable and keeps the 500-char counter;
- moment/time/location confirmation remains backed by real profile/browser/user-selected data;
- no-credit state is visually calm and product-safe;
- history section and empty state match oracle language/density where compatible with real data.

The screen may use the same visual language introduced in Wave 04 where useful, but do not make broad global theme changes.

### 5.2 Loading, error, and ready states

Improve the public state contract without rewriting the business flow:

- Loading state should expose `data-testid="horary-loading"` and `role="status"`.
- Root screen should expose `data-testid="horary-screen"`.
- Root screen should expose `data-state="loading|ready|error"`.
- If the initial `Promise.all([quota, questions, profile])` fails, render a visible error block with:
  - `data-testid="horary-load-error"`
  - `role="alert"`
  - retry button that re-runs the real `loadData()` path.
- Do not silently turn load failure into no-credit state.

### 5.3 UI Semantic/Test Contract

Expose stable selectors and accessibility states:

- `data-testid="horary-screen"` on root;
- root `data-state="loading|ready|error"`;
- root `data-has-credit="true|false"` when ready;
- `data-testid="horary-back-link"`;
- `data-testid="horary-header"`;
- `data-testid="horary-quota-section"`;
- `data-testid="horary-quota-bar"` already exists and must remain;
- `data-testid="horary-form-section"` when form renders;
- `data-testid="horary-form"` on the form element;
- `data-testid="horary-no-credit-card"` when no spendable credit;
- `data-testid="horary-history-section"`;
- `data-testid="horary-empty-history"` when no questions;
- `data-testid="horary-question-card"` already exists and must remain for history rows;
- `data-testid="horary-processing-card"` already exists and must remain;
- category buttons keep `data-testid="horary-category-<key>"` and add `aria-pressed`;
- submit button keeps `data-testid="horary-submit-btn"` and uses native `disabled` when submitting or invalid;
- submit/API error uses `data-testid="horary-submit-error"` and `role="alert"`;
- blocked validation reason uses `data-testid="horary-blocked-reason"` and `role="alert"` or `role="status"` depending on severity;
- icon-only buttons, if any are introduced, must have `aria-label`.

Tests must not depend on Tailwind class names.

Do not submit a real question in mock visual e2e unless you add method-aware route fixtures and keep it fully test-only. Unit/component tests already cover submit behavior.
