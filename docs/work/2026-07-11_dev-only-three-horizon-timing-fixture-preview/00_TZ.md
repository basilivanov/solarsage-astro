## Цель

Пользователь должен иметь возможность открыть в обычном браузере, а не только в
Playwright route interception, fixture с трёхгоризонтным Why и увидеть timing
строки в Next dev preview на `3003`.

Канонический URL для демонстрации:

```text
http://127.0.0.1:3003/day/2026-07-08?fixture=three-horizon-timing&why=1
```

Без `fixture=three-horizon-timing` обычный экран дня обязан сохранить текущий
реальный auth/API flow.

## Поведение dev URL

1. URL с `fixture=three-horizon-timing` не должен ждать Telegram auth и не
   должен запрашивать реальный `/api/day/...`.
2. Он рендерит существующий `TodayScreen` с contract-valid fixture data и
   подходящим локальным access state.
3. `?why=1` открывает Why block как обычно.
4. В трёх horizon cards видны именно эти строки:

```text
Действует: 12 мая 2026 — 11 мая 2027
Сейчас: Фон уже действует

Активно: 3 июля 2026 — 18 июля 2026
Пик: 10 июля 2026, 11:32
Сейчас: Набирает силу

Активно: 7 июля 2026 — 9 июля 2026
Пик: 8 июля 2026, 05:00
```

5. Для evidence без timing-полей production UI не должен показывать пустой
   timing-container.

## Реализация

Выбери минимальную изолированную dev-only точку интеграции. Допустим отдельный
локальный fixture endpoint/harness или page-level development guard; предпочтение
решению, где browser URL работает напрямую, а normal `useDay` не получает
feature-flag и не меняет API request. Любое чтение fixture должно происходить
только после development guard.

Нужны public DOM contracts:

- `data-testid="why-time-horizon-timing"` на каждом timing контейнере;
- fixture root marker, например `data-testid="dev-timing-fixture"`, чтобы
  browser/Playwright проверяли, что именно dev fixture активирован.
