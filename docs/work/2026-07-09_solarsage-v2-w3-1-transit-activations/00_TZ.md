  - `unsupported_technique_deferred:annual_profection`

### 2. Build raw natal + transit context in sidecar

In the sidecar builder:

- calculate birth JD from request birth date/time/tz;
- calculate target JD from target date/time/tz;
- calculate natal planet positions;
- calculate target transit planet positions;
- calculate natal houses and special points from birth coordinates;
- derive all four angles:
  - `ASC` from sidecar special point;
  - `MC` from sidecar special point;
  - `DSC = (ASC + 180) % 360`;
  - `IC = (MC + 180) % 360`;
- preserve `house_system` from calculation, unless request explicitly requires a supported house system.

Do not hardcode Basil data or expected outputs.

### 3. Canonical aspect extraction

Load aspect rules from:

```text
grace/canon/aspect_rules.v1.yml
```

Use this canonical map:

```python
ASPECT_ANGLES = {
    "conjunction": 0,
    "semi_sextile": 30,
    "semi_square": 45,
    "sextile": 60,
    "square": 90,
    "trine": 120,
    "sesqui_quadrate": 135,
    "quincunx": 150,
    "opposition": 180,
}
```

Canonical keys in YAML are uppercase; activation output uses lowercase names above.

Orb rule for W3.1:

- use `orb_profile_default[target_key]` if available;
- else use `orb_profile_default[source_planet]` if available;
- else fallback to `5.0`.

For each transit-to-target pair:

- compute angular distance normalized to `0..180`;
- find the closest canonical aspect within max orb;
- compute `orb`;
- compute `strength` deterministically in `0..1`;
- classify polarity:
  - `trine`, `sextile` -> `supportive`;
  - `square`, `opposition`, `semi_square`, `sesqui_quadrate` -> `tense`;
  - `conjunction` -> `mixed`;
  - all other aspects -> `neutral`;
- set `phase` and `applying` by comparing current orb with orb at `target_jd + 0.1` days:
  - future orb smaller -> `applying=True`, `phase="applying"`;
  - future orb larger -> `applying=False`, `phase="separating"`;
  - equal within tolerance -> `phase="exact"`;
- `exact_at` may remain `None` in W3.1 unless you implement a deterministic scan/refinement. Do not fake exact timestamps.

Strength rule:

- use aspect weight from `aspect_rules.v1.yml:aspect_weights`;
- combine with orb factor: `max(0, 1 - orb / max_orb)`;
- clamp to `0..1`;
- round to 4 decimals.

### 4. Generate `transit_to_natal`

For each transit planet and each natal planet:

- target type: `planet`;
- target key: uppercase natal planet name;
- source frame: `transit`;
- target frame: `natal`;
- technique: `transit_to_natal`;
- family: `transit`;
- evidence string must include frame:
  - `Transit Moon opposition natal Pluto, orb 1.0454°`

Index:

- add activation id to `by_planet[target_key]`.

Expected Basil evidence for `2026-07-08 12:00 Europe/Moscow`:

- `Transit Moon opposition natal Pluto`
- orb close to `1.0454°` with tolerance `<= 0.05°`.

### 5. Generate `transit_to_angle`

Targets:

- `ASC`
- `DSC`
- `MC`
- `IC`

For each transit planet and angle:

- target type: `angle`;
- target key: angle name uppercase;
- target frame: `angle`;
- technique: `transit_to_angle`;
- family: `transit`;
- set `angle=<angle name>`;
- evidence string must include frame:
  - `Transit Saturn trine natal MC, orb 1.2345°`

Index:

- add activation id to `by_angle[angle]`.

### 6. Generate `transit_planet_in_house`

For each transit planet:

- find the natal house that contains its target longitude using natal house cusps;
- target type: `house`;
- target key: house number as string;
- source frame: `transit`;
- technique: `transit_planet_in_house`;
- family: `transit`;
- `strength=1.0`;
- `polarity="neutral"`;
- evidence:
  - `Transit Mars in natal house 12, strength 1.00`

Index:

- add activation id to `by_house[str(house)]`.

### 7. Generate lots and `transit_to_lot`

Compute at least these lots:

- `FORTUNE`
- `SPIRIT`
- `EROS`
- `MARRIAGE`
- `NECESSITY`
- `VICTORY`
- `NEMESIS`

Each lot must include debug fields:

```json
{
  "name": "FORTUNE",
  "longitude": 123.45,
  "house": 2,
  "formula": "fortune_day_asc_moon_sun"
}
```

Use deterministic day/night formulas. For W3.1:

- determine day chart by Sun house: day if natal Sun is in houses `7..12`, night otherwise;
- normalize every formula result to `0..360`;
- find lot house via natal house cusps.

Formula table:

```text
FORTUNE:
  day:   ASC + Moon - Sun
  night: ASC + Sun - Moon
SPIRIT:
  day:   ASC + Sun - Moon
  night: ASC + Moon - Sun
EROS:
  day:   ASC + Venus - Spirit
  night: ASC + Spirit - Venus
NECESSITY:
  day:   ASC + Fortune - Mercury
  night: ASC + Mercury - Fortune
VICTORY:
  day:   ASC + Jupiter - Spirit
  night: ASC + Spirit - Jupiter
NEMESIS:
  day:   ASC + Fortune - Saturn
  night: ASC + Saturn - Fortune
MARRIAGE:
  non-reversing: ASC + DSC - Venus
```

Formula source notes:

- Hermetic lots formulas are based on the publicly documented lot table at `https://www.twowander.com/blog/what-are-hermetic-lots-arabic-parts`.
- `MARRIAGE` is not one of the seven Hermetic lots in that table; use the documented general Arabic Part formula `ASC + DSC - Venus` and record `formula="marriage_asc_dsc_venus_non_reversing"` in debug.

For each transit planet and lot:

- technique: `transit_to_lot`;
- family: `transit`;
- target type: `lot`;
- target key: lot name uppercase;
- set `lot=<lot name>`;
- source frame: `transit`;
- target frame: `lot`;
- evidence:
  - `Transit Venus trine lot FORTUNE, orb 1.2345°`

Index:

- add activation id to `by_lot[lot_name]`.
