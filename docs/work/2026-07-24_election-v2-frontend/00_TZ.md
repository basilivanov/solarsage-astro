# ТЗ — Election v2, фронт: порт одобренного прототипа в React

Дата: 2026-07-24
Ветка: `feat/election-v2-frontend` (создаёт ревьюер от main ПОСЛЕ merge backend)
Исполнитель: кодер в tmux astro2. Коммитит ревьюер.

## Контекст

Эталон — файл `public/election-proto.html` (одобренный владельцем прототип, открыть можно на dev). Задача: портировать его В ТОЧНОСТИ в React-раздел election, заменив текущий (components/readings/election/*, app/(grace)/readings/election/*), и подключить к реальному API election v2 (бэк из `feat/election-v2-backend`, уже в main).

API (main): `POST /api/election/searches` {eventType: "cat:sub" или "sub", windowFrom, windowTo, idempotencyKey, clientTimezone?} → 201; GET `searches/{id}` → {eventType, windowFrom, windowTo, status, result}. result (passthrough): `{event, facts{days}, best_days[{date, score, label, reasons, moon_sign_ru, phase_pct, voc_intervals}], avoid_days[...], narrative{hero_reason, hero_personal, hero_plain, hero_hours, day_notes[], avoid_notes[]}}`.

## Что делать

### 1. Форма (`election-form.tsx` — переписать)

Порт 1:1 с прототипа:
- Заголовок «Лучшие дни по звёздам» + подзаголовок.
- Сетка 2×3 из 6 базовых категорий (иконки-emoji + название; данные из `GET`-рендера канона — захардкодить список в `lib/contracts/election.ts` как const, тот же порядок/label/emoji что в прототипе).
- Тап по категории → под ней раскрываются подкатегории чипсами (`subs` из того же const); тап по подкатегории — её label попадает в editable поле «Свой запрос (можно править)» (сохранить поведение: поле всегда видимо, текст редактируем; тап по полю — режим custom).
- Окно: segmented «Неделя/2 недели/Месяц/Свои» (дефолт 2 недели; «Свои» — два date-инпута, max 62 дня).
- CTA «Подобрать даты ✨» — disabled без выбранной подкатегории/custom-текста или без кредитов (quota-bar как у хорара, общий кошелёк).
- eventType в запрос: `"cat:sub"`.

### 2. Processing (`election-processing-card.tsx`)

Порт: луна SVG + 3 шага с теми же текстами («Смотрим Луну на твоё окно…», «Считаем фазы, знаки и холостой курс…», «Выбираем лучшие дни лично для тебя…»), pulse-анимация.

### 3. Результат (`election-result-view.tsx` — переписать)

Порт 1:1, данные из result.facts + result.narrative:
- Hero: дата (serif, день недели), бейдж по label (great=«Отличный день», good=«Хороший день»), `narrative.hero_reason`, строка Луны (`Растущая Луна, {phase_pct}% · знак: {moon_sign_ru}` — waxing→«Растущая», иначе «Убывающая»), золотой блок `narrative.hero_hours`, раскрывашка «Почему этот день?» → блоки «Астрологически» (hero_personal), «Простыми словами» (hero_plain), плюс engine reasons как есть (мелким списком ниже, без ярлыков).
- «Ещё хорошие дни»: карточки по best_days[1..] + day_notes по дате (матчить по date).
- «Лучше не начинать»: avoid_days + avoid_notes (заголовок — engine reason первой строкой, тело — narrative note).
- **Календарь окна**: сетка месяца hero-даты, классы `best/good/avoid` по days-фактам, today-обводка, тап по отмеченному дню → текст под сеткой (day_note или avoid_note; если нет narrative — engine reasons).
- Кнопка «Новый подбор» → форма.

Стили — Tailwind-классы, повторяющие CSS прототипа (цвета через токены проекта: bg-card, border-border, accent; скругления rounded-2xl; serif — font-serif). data-testid контракт по AGENTS.md: `election-screen`, `election-form`, `election-result-view`, `election-hero`, `election-best-day-{date}`, `election-avoid-day-{date}`, `election-calendar`, `election-calendar-day-{date}`.

## Подводные камни

- Визуал = прототип. Не «улучшать» от себя: отступы/скругления/тени/цвета — как в election-proto.html.
- result.narrative может отсутствовать у старых записей (до v2) — рендерить тогда engine reasons (facts) без narrative-блоков, не падать.
- Emoji в React-строках — как текст, не компоненты.
- НЕ коммитить. НЕ трогать бэк, прототип, horary.
