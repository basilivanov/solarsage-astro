## 0. Executive summary

W9 fixed the largest proof-quality problems from W8: audit mode split, explicit live/frozen commands, `artifact_source.json`, sidecar activation artifact export, version constants, and Feb 29 profection hardening.

The remaining blockers are narrower but still acceptance-critical:

1. **V2 cache read/write identity mismatch**: cache read identity can still use `frontend_payload_version=1` while the selected V2 write path emits `frontend_payload_version=2`.
2. **V2 meta/body contract mismatch**: a payload can declare `payload_version=today.v2` and `frontend_payload_version=2` while `payload.v2` is absent because the body is still gated by `SOLARSAGE_V2_FRONTEND_ENABLED`.
3. **Live audit proof gap**: live audit fetches sidecar activation layer and separately calls `TodayService`, but does not yet prove that the final V2 payload contains/reflects the sidecar activation evidence.
4. **Runtime flag provenance gap**: `artifact_source.json` does not yet include feature flags, selected scoring version, final payload version, frontend payload version, or whether the final payload has a non-null V2 block.

W10 must close these exact gaps without expanding astrology functionality.

The final desired state:

```text
If selected scoring is ss-scoring-2.0:
  cache read key == cache write key
  TodayPayload.meta.payload_version == today.v2
  TodayPayload.meta.frontend_payload_version == 2
  TodayPayload.v2 is non-null
  TodayPayload.v2.activation_evidence is non-empty when sidecar activations exist
  live audit proves sidecar activations are represented in the final payload or reports unmapped ids
```

## 3. Required architectural rule

### 3.1 Selected scoring version is the source of truth

The selected scoring version must control the payload/cache identity.

If:

```python
str(selected_scoring_version) == SCORING_V2_VERSION
```

then the run is a V2-selected run, regardless of `SOLARSAGE_V2_FRONTEND_ENABLED`.

For a V2-selected run:

```python
calculation_version = CALCULATION_VERSION              # ss-calc-1.1.0
activation_layer_version = ACTIVATION_LAYER_VERSION    # al-1.0 or layer-provided value
scoring_version = SCORING_V2_VERSION                   # ss-scoring-2.0
payload_version = TODAY_V2_PAYLOAD_VERSION             # today.v2
frontend_payload_version = V2_FRONTEND_PAYLOAD_VERSION # 2
payload.v2 must be non-null
```

For a V1-selected run:

```python
calculation_version = LEGACY_CALCULATION_VERSION       # 1
scoring_version = LEGACY_SCORING_VERSION               # 1
payload_version = TODAY_V1_PAYLOAD_VERSION             # today.v1
frontend_payload_version = LEGACY_FRONTEND_PAYLOAD_VERSION # 1
payload.v2 may be null
```

### 3.2 `SOLARSAGE_V2_FRONTEND_ENABLED` must not define wire identity

`SOLARSAGE_V2_FRONTEND_ENABLED` may control frontend rendering rollout, but it must not make the backend emit a contradictory payload.

Forbidden state:

```json
{
  "meta": {
    "payload_version": "today.v2",
    "frontend_payload_version": 2,
    "scoring_version": "ss-scoring-2.0"
  },
  "v2": null
}
```

Allowed choices:

Choice A, preferred:

```text
If selected scoring is V2, always build payload.v2.
Frontend may ignore it if the UI flag is off.
```

Choice B, fallback if product insists:

```text
If frontend flag is off, keep payload_version=today.v1/frontend=1 even if internal scoring selected V2.
```

For W10 use **Choice A**.

Reason: W9 already moved toward “V2-selected path emits V2 identity even if frontend flag is off.” W10 should complete that approach by always emitting a valid V2 body.

This can emit a V2 payload identity with no V2 body.

### 4.2.2 Required behavior

Compute once:

```python
v2_selected = str(scoring_version) == str(SCORING_V2_VERSION)
```

Use `v2_selected` for backend contract generation:

```python
include_v2_payload_body = v2_selected
```

Then:

1. `why_evidence_packet` should be built when `v2_selected` and the required V2 inputs exist.
2. `TodayInterpretationService.build(...)` should receive `activation_layer` and `scoring_v2_result` when `v2_selected`.
3. `v2_block` should be built when `v2_selected`.
4. If `v2_selected` but `dual.v2_result is None`, handle explicitly.

### 4.2.3 Handling `v2_selected` but `dual.v2_result is None`

This state should normally not happen in a real V2 selected path.

It can happen in tests if they mock `DualRunResult(selected_scoring_version=SCORING_V2_VERSION, v2_result=None)`.

Decide one of two policies:

Policy A, strict production:

```python
if v2_selected and dual.v2_result is None:
    raise RuntimeError("V2 selected but v2_result is missing")
```

Policy B, safer compatibility:

```python
if v2_selected and dual.v2_result is None:
    build a minimal V2 block with:
      activation_summary from activation_layer
      activation_evidence from activation_layer.activations
      score_breakdown empty or marked unavailable
      why_today derived from activation evidence
      audit.available=False
      audit.warning="v2_result_missing"
```

For W10 use **Policy A for production**, and adjust tests to provide a real/mocked `ScoringV2Result` when selected V2 is expected.

Reason: a V2-selected path without `v2_result` is a contract violation. Failing loudly is safer than silently emitting a pseudo-V2 payload.

### 4.3.3 Required evidence mapping contract

Each V2 activation evidence item in payload must preserve or expose the source activation id.

Acceptable shapes:

```json
{
  "id": "t2n__MOON__PLUTO",
  "source_activation_id": "t2n__MOON__PLUTO",
  "technique": "transit_to_natal",
  "technique_family": "transit",
  "evidence": "Transit Moon opposition natal Pluto..."
}
```

or simply:

```json
{
  "id": "t2n__MOON__PLUTO",
  "technique": "transit_to_natal",
  ...
}
```

The live audit must be able to compute:

```python
sidecar_ids = {a.id for a in sidecar_activation_layer.activations}
payload_ids = {e.id or e.source_activation_id for e in payload.v2.activation_evidence}
unmapped = sidecar_ids - payload_ids
```

### 4.3.4 Filtering policy

If not all sidecar activation ids are shown in final payload because of UI top-N filtering, this is allowed only if:

1. `payload.v2.audit` or another debug field records the mapping summary;
2. live audit writes `activation_evidence_mapping.json` with:

```json
{
  "sidecar_activation_count": 25,
  "payload_activation_evidence_count": 10,
  "mapped_ids": [...],
  "unmapped_ids": [...],
  "filter_policy": "top_n_payload_evidence",
  "accepted_unmapped": true
}
```

For W10, preferred simpler rule:

```text
Payload V2 activation_evidence should contain all sidecar activation ids.
```

If this is too heavy for frontend, include all ids in dev/audit part while UI renders top-N.
