# ТЗ — Today считать только запрошенный день, отключить недельный prefetch

Дата: 2026-07-15

Исходный HEAD: `65ee359` (`fix(api): deny dev auth outside local development`)

Новая ветка: `fix/today-single-day-no-week-prefetch`

Исполнитель: кодер в `tmux astro:0.0`

Роль архитектора: постановка, review и приёмка; production code архитектор сам не меняет.

## 1. Цель

После запроса `GET /api/day/{date}` рассчитывать и кэшировать только реально запрошенный `target_date`.

Полностью отключить текущий background fan-out `today - 3 ... today + 3`, который после cold Today response запускает до семи повторных `get_today_payload()` и фактически создаёт до шести дополнительных тяжёлых расчётов соседних дат.

Это временная cost/reliability политика:

- жертвуем быстрым первым открытием соседних дней;
- не тратим sidecar/DB/LLM ресурсы на даты, которые пользователь может не открыть;
- вернуть prefetch можно только отдельной будущей задачей с job queue, access-aware policy, distributed dedupe, cost budget и hit-rate metrics.

## 2. Важно: что именно отключаем

Текущий runtime:

```text
request target date
  -> foreground Today pipeline
  -> cache target date
  -> asyncio.create_task(_prefetch_week)
       -> dates target-3 ... target+3
       -> independent DB session per date
       -> full get_today_payload per date
       -> sidecar/scoring/LLM/cache
```

Новый runtime:

```text
request target date
  -> foreground Today pipeline
  -> cache target date
  -> return
```

Никаких background Today calculations после response.

## 3. Не путать с другими семидневными структурами

### 3.1. `week_strip` оставить

В `TodayPayload` сейчас формируется семь дешёвых navigation rows:

```python
week_strip=[... for i in range(7)]
```

Это публичная UI-структура, а не семь расчётов. Её не менять:

- количество элементов остаётся 7;
- даты `target_date ± 3` остаются;
- wire contract/frontend не меняются.

### 3.2. Yesterday delta оставить

`_get_yesterday_signals()` получает deterministic signals предыдущего дня для сравнения/DayDelta. Это не полный соседний Today payload и не LLM narrative job.

В этой задаче его не удалять и не менять.

Таким образом, решение означает «один полный Today narrative/payload за запрос», а не запрет любого чтения астрономических данных соседней даты.

### 3.3. Calendar не менять

`CalendarService` и его range behavior — отдельный пункт аудита. Не исправлять его в этом change-set.

## 5. Exact production change

Файл:

```text
apps/api/app/services/today_service.py
```

### 5.1. Удалить prefetch-only imports

После удаления механизма в этом модуле больше не нужны:

```python
import asyncio
from app.core.config import settings
from app.db.session import SessionLocal
```

Удалить их. Не трогать `AsyncSession`: он нужен основному сервису.

Перед удалением убедиться через `rg`, что в `today_service.py` эти symbols используются только prefetch-кодом.

### 5.2. Удалить process-local task ownership set

Полностью удалить:

```python
# Strong-reference set for best-effort background prefetch tasks.
_TODAY_PREFETCH_TASKS: set[asyncio.Task[None]] = set()
```

Не заменять его другим task registry, queue или feature flag.

### 5.3. Удалить scheduling после cache write

После:

```python
await self._cache_payload(...)
```

полностью удалить блок:

```python
# W-5.2: Prefetch week in background (don't block user)
if not skip_prefetch and settings.app_env != "test":
    prefetch_task = asyncio.create_task(self._prefetch_week(user_id, target_date))
    _TODAY_PREFETCH_TASKS.add(prefetch_task)
    prefetch_task.add_done_callback(_TODAY_PREFETCH_TASKS.discard)
```

После cache write должен сразу выполняться `return payload`.

Не добавлять `BackgroundTasks`, `ensure_future`, thread, queue, cron или side effect в другом месте.

### 5.4. Полностью удалить `_prefetch_week`

Удалить весь метод:

```python
async def _prefetch_week(...)
```

включая:

- список `today ± 3`;
- `_calc_one`;
- `SessionLocal()`;
- `asyncio.gather`;
- prefetch warning logs.

Не оставлять no-op stub: наличие метода создаст ложный runtime contract и возможность случайного повторного включения.

### 5.5. `skip_prefetch` временно сохранить как compatibility parameter

Сигнатуру пока не ломать:

```python
skip_prefetch: bool = False
```

Причина: параметр используется большим числом внутренних тестов/call sites. Его массовое удаление не нужно для runtime-результата и расширит scope.

После удаления prefetch параметр становится compatibility no-op. Сделать это правдиво:

- в function contract написать, что `skip_prefetch` сохранён временно для совместимости и игнорируется, потому что background prefetch отключён;
- в начале `get_today_payload()` допустимо добавить:

  ```python
  del skip_prefetch  # compatibility-only; week prefetch is disabled
  ```

  только если это не мешает читаемости/тестам;
- не использовать параметр для новой логики.

Не менять его default и position: signature compatibility test должен остаться зелёным.

### 5.6. Обновить GRACE contract/map

В module contract:

- удалить invariant про background week prefetch;
- добавить invariant:

  ```text
  A foreground Today request never schedules calculations for adjacent dates.
  ```

- `side_effects`/function contract не должны обещать background task;
- `CACHE_LAYER` описывает только read/write requested target date;
- при необходимости добавить non-goal: speculative adjacent-day materialization disabled.

Не переписывать остальной большой файл ради формата.

## 8. Cache и данные

Существующие cache rows для соседних дат оставить:

- они валидны по текущим versioned keys;
- их удаление создаст лишнюю стоимость;
- новый код просто перестанет создавать speculative rows;
- открытие уже cached соседней даты останется быстрым до естественной инвалидизации.

Cache invalidation не нужна, потому что payload schema/calculation/content versions не меняются.
