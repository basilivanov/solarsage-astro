## Цель

Показать совместимость двух натальных карт на двух уровнях одновременно:

1. быстрый человеческий вывод — где легко, где нормально, где сложно;
2. видимый астрологический слой — аспекты, орбисы, наложение домов и подробное объяснение каждого контакта.

Прототип mobile-first и не затрагивает React. Файлы находятся в `public/prototypes/synastry/`.

## Список сравнений

- поиск по имени;
- фильтры `Хорошо подходит / Нормально / Сложно`;
- общий балл;
- баланс поддерживающих, неоднозначных и напряжённых контактов;
- отдельный демонстрационный пример с преимущественно напряжённой синастрией.

## Добавление партнёра

Форма принимает имя, тип связи, дату, время и выбранное место рождения.
Место обязано разрешиться в координаты и IANA timezone; свободный текст без
выбранной подсказки нельзя отправить в расчёт.

Рядом с полем времени есть переключатель **«Точное время неизвестно»**:

- поле времени очищается и блокируется;
- пользователь может продолжить расчёт;
- форма показывает, что планеты и основные аспекты сохраняются;
- ASC и дома партнёра не рассчитываются;
- положение Луны и итоговый балл помечаются как менее точные;
- результат получает состояние `approximate`, а не маскируется под точный.

При этом направления различаются: планеты партнёра всё ещё можно наложить на
дома пользователя, потому что owner houses известны; планеты пользователя на
дома партнёра при unknown time недоступны.

При повторном отключении переключателя ранее введённое время восстанавливается.

## Подробный отчёт пары

- двухкольцевое наложение карт;
- цветные линии аспектов;
- точные подписи `планета → аспект → планета` и орбис;
- домовые наложения;
- человеческий перевод ключевых контактов;
- сферы `Близость / Общение / Быт / Дела и деньги`;
- проверка реальностью `Да, очень / Частично / Не похоже`.

## Drill-down одного аспекта

Любая строка аспекта и техническая подпись в карточке перевода кликабельны. По нажатию открывается mobile sheet.

Sheet обязан содержать:

1. **Что соединяется** — функция планеты пользователя и функция планеты партнёра.
2. **Как работает аспект** — отдельное объяснение соединения, тригона, секстиля, квадрата, оппозиции или квиконса.
3. **Как проявляется в жизни** — несколько коротких сцен вместо общего психологического текста.
4. **Что помогает** — конкретные действия пары.
5. **Что это не означает** — защита от фатализма и оценок интеллекта или личности.

Для `Меркурий □ Меркурий` обязательны примеры:

- переписка и неверно услышанный тон;
- разный порядок обсуждения планов;
- конфликт «я такого не говорил» против «но это так прозвучало»;
- разная память о ключевых словах разговора;
- техника пересказа `я услышал, что… Верно?`;
- рекомендация не решать чувствительные темы короткими сообщениями.

## Контракт данных аспекта

```json
{
  "ownerPlanet": "Mercury",
  "partnerPlanet": "Mercury",
  "aspect": "square",
  "orbDegrees": 1.05,
  "tone": "supportive | mixed | tense",
  "short": "Смысл теряется в форме",
  "confidence": "high | medium | low",
  "excludedFromScore": false
}
```

## Точность данных рождения

```json
{
  "birthTimePrecision": "exact | unknown",
  "ownerHousesAvailable": true,
  "partnerHousesAvailable": true,
  "ownerAscAvailable": true,
  "partnerAscAvailable": true,
  "partnerMoonPrecision": "exact | approximate",
  "reportPrecision": "exact | approximate"
}
```

При `birthTimePrecision = unknown` значения `partnerHousesAvailable` и
`partnerAscAvailable` обязаны быть `false`; owner flags остаются true.

## Правила LLM

- Техническая астрология не скрывается, но не выдаётся простынёй.
- Сначала точный фактор, затем человеческий перевод.
- Один insight — одна мысль и одна сфера жизни.
- Каждое напряжение обязано иметь способ настройки.
- Запрещены абсолюты: `обречены`, `идеальная пара`, `никогда`, `точно изменит`.
- Нельзя оценивать интеллект или качество человека по напряжённому Меркурию.
- Нельзя приписывать намерения: аспект описывает способ взаимодействия, а не доказывает ложь, контроль или измену.
- Неизвестное время рождения явно снижает точность; домовые наложения в этом случае не придумываются.

## Будущее расшаривание

Точка интеграции расшаривания сохранена, но сейчас выключена. Публичный snapshot должен уметь включать или исключать технический астрологический слой по выбору пользователя.

## Удаление данных

Владелец может удалить партнёра. Удаляются birth PII, report narrative,
aspect details и feedback; обезличенная запись расхода/возврата кредита остаётся
для финансового audit и не содержит имени, даты, места или LLM-текста.
