# Синастрия / совместимость — HTML prototype & LLM content contract

## Цель экрана

Пользователь добавляет людей по данным рождения и быстро видит три вещи:

1. **Общий вывод:** хорошо подходит / нормально / сложно.
2. **Астрологическое основание:** какие планеты образуют аспекты, с каким орбисом и что попадает в какие дома.
3. **Человеческий перевод:** как конкретная связка проявляется в общении, близости, быту, работе и конфликтах.

Прототип mobile-first. React и production API не затрагиваются.

## Информационная архитектура v2

### 1. Список сравнений

- Поиск по имени.
- Фильтры состояния: `Все`, `Хорошо подходит`, `Нормально`, `Сложно`.
- Фильтры не сортируют людей по сферам и не меняют баллы.
- Карточка показывает общий балл, короткий вывод и баланс астрологических контактов:
  - поддерживают;
  - неоднозначны;
  - напрягают.
- В данных обязательно должен быть жёсткий негативный пример, чтобы дизайн честно выдерживал сценарий, где почти всё напряжённое.

### 2. Подробный отчёт пары

Порядок блоков:

1. Общий балл и прямой вывод.
2. Баланс поддерживающих / неоднозначных / напряжённых контактов.
3. **Видимая карта взаимодействия:** два кольца планет и цветные линии аспектов.
4. Ключевые аспекты с точным типом и орбисом.
5. Наложение домов: `чья планета → чей дом`.
6. Человеческий перевод сильнейших связок.
7. Разбор по жизненным сферам.
8. Проверка «Похоже на вас?».

Астрологический слой не прячется в optional-подвале. Он является самостоятельным продуктовым слоем, но не заменяет человеческий перевод.

## Цветовая семантика

- Зелёный — поддерживающий аспект или устойчивая лёгкость.
- Янтарный — смешанный, нестабильный или требующий настройки контакт.
- Красный — напряжённый аспект и зона регулярного трения.

Красный не означает «плохой человек» или «отношения обречены». Он означает: контакт чаще требует осознанных правил, границ или ремонта.

## Градация списка

- `Хорошо подходит` — поддерживающих факторов заметно больше, основные жизненные сферы не конфликтуют.
- `Нормально` — есть ресурс и интерес, но несколько ключевых зон нестабильны.
- `Сложно` — напряжённые факторы доминируют или затрагивают базовые темы: безопасность, коммуникацию, власть, доверие.

Порог не должен строиться только на арифметической сумме аспектов. Вес зависит от:

- точности орбиса;
- типа планет;
- повторения одной темы несколькими факторами;
- попадания в угловые и значимые дома;
- точности исходных данных рождения.

## Контракт одного астрологического контакта

```json
{
  "technical": {
    "owner_point": "Moon",
    "partner_point": "Venus",
    "aspect": "trine",
    "orb_degrees": 1.2,
    "tone": "supportive"
  },
  "headline": "Тепло считывается без объяснений",
  "human_effect": "что происходит между людьми",
  "observable_scene": "конкретная узнаваемая ситуация",
  "repair_or_use": "как использовать силу или ремонтировать трение",
  "weight": 0.86,
  "confidence": "high"
}
```

### Обязательные требования

- На карточке всегда видны планеты, аспект и орбис.
- У каждого технического фактора есть человеческий перевод.
- Для напряжённого фактора обязателен `repair_or_use`.
- Один фактор — одна поведенческая мысль.
- Нельзя писать «эмоциональная напряжённость» без описания, **как именно** она выглядит.

## Контракт наложения домов

```json
{
  "source_person": "partner",
  "planet": "Venus",
  "target_person": "owner",
  "house": 7,
  "headline": "Быстро воспринимается как партнёр",
  "human_effect": "чем именно человек включает эту сферу жизни",
  "confidence": "exact | approximate | unavailable"
}
```

Если время рождения неизвестно, домовое наложение для соответствующей карты нельзя придумывать. UI должен написать, что слой недоступен или приблизителен.

## Контракт человеческого перевода

```json
{
  "headline": "Поддержка ощущается как суд",
  "technical_basis": ["Saturn square Moon, orb 0°19′"],
  "observable_behavior": "Когда одному нужна поддержка, второй отвечает оценкой, правилами или дистанцией.",
  "scene": "Один говорит, что ему больно, а получает разбор ошибок.",
  "repair": "Сначала признать чувство, затем отдельно обсуждать решение.",
  "severity": "high"
}
```

## Ограничения текста

- Заголовок: до 7 слов.
- Основная мысль: 1–3 коротких предложения.
- Конкретная сцена выносится в отдельный визуальный блок.
- Длинный текст разбивается на карточки и раскрывающиеся сферы.
- Не смешивать близость, быт, деньги и работу в одном insight.
- Запрещены абсолюты: «обречены», «идеальная пара», «точно изменит», «никогда».
- Не ставить диагнозы и не приписывать намерения.
- Не романтизировать ревность, контроль, нарушение границ и наказание молчанием.
- При доминировании красных факторов вывод должен быть прямым, а не сглаженным эвфемизмами.

## UX-инварианты для реализации

- Список не превращается в рейтинг «кандидатов на человека»; это фильтруемый обзор сохранённых сравнений.
- Астрологическая схема видна сразу внутри пары.
- Нажатие на аспект подсвечивает соответствующую линию на схеме.
- Технический и человеческий слои связаны, но визуально разделены.
- Неизвестное время рождения явно отключает или снижает точность домов.
- Негативный отчёт визуально и текстово остаётся негативным.
- Проверка «совпало / частично / не похоже» не изменяет рассчитанную карту задним числом.
