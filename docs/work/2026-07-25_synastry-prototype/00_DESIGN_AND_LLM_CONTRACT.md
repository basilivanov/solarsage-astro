# Синастрия / совместимость — HTML prototype & LLM content contract

## Цель экрана

Дать владельцу натальной карты возможность быстро добавить любого человека и сравнить несколько пар между собой. Первый уровень отвечает на вопрос «с кем мне легче в нужной сфере?», второй — «как именно это проявляется в обычной жизни и что с этим делать?».

Прототип mobile-first и не затрагивает React. Файлы в `public/prototypes/synastry/` предназначены для ручного просмотра и согласования UX перед реализацией.

## Информационная архитектура

1. **Список сравнений**
   - Добавить человека.
   - Лучшее совпадение в выбранной сфере.
   - Фильтры: в целом, близость, быт, дела, поездки.
   - Карточка человека: балл, короткая градация, одна сильная сторона, одна зона настройки, точность данных.

2. **Подробный отчёт пары**
   - Общий балл и человеческая формулировка.
   - Краткий вывод в 2–3 предложениях.
   - Отдельные вкладки по жизненным сценариям.
   - Три слоя: что работает, где цепляет, что помогает.
   - Проверка «Похоже на вас?».
   - Опциональное объяснение метода без астрологической терминологии.

3. **Добавление человека**
   - Имя, тип связи, дата, время, место рождения.
   - Режим «точное время неизвестно» снижает точность и показывает примерный балл.
   - Данные приватны, уведомление человеку не отправляется.

4. **Будущее расшаривание**
   - В detail-header оставлена стабильная кнопка `data-future="share"`, сейчас `disabled`.
   - Для публичного snapshot/link не потребуется менять структуру detail screen.

## Градация вместо «стрём / норм»

- 87–100 — **Очень легко**
- 78–86 — **Сильное совпадение**
- 68–77 — **Есть потенциал**
- ниже 68 — **Нужна настройка**

Это градация относительной лёгкости в конкретной сфере, а не оценка качества человека и не предсказание исхода отношений.

## LLM content contract

### Основной принцип

LLM не пересказывает астрологические факторы. Он переводит их в наблюдаемую динамику пары.

Плохо:

> Его Луна в квадрате к твоему Марсу, поэтому возможна эмоциональная напряжённость.

Хорошо:

> Когда один уже хочет действовать, второму сначала нужно прожить эмоцию. Из-за этого инициатива может звучать как давление. Помогает заранее спросить: «тебе сейчас поддержка или решение?»

### Обязательная структура одного insight

```json
{
  "headline": "до 7 слов",
  "observable_behavior": "что пользователь реально замечает в жизни",
  "trigger": "в какой ситуации это включается",
  "repair": "конкретное действие пары",
  "confidence": "high | medium | low"
}
```

### Ограничения текста

- Заголовок: до 7 слов.
- Объяснение: до 220 символов, одна мысль на карточку.
- Один insight не смешивает близость, быт и работу.
- Каждая зона трения обязана иметь `repair` / конкретное действие.
- Сначала вывод для человека, а не техническая причина.
- Запрещены абсолюты: «всегда», «никогда», «обречены», «идеальная пара», «точно изменит».
- Использовать калиброванный язык: «может», «чаще», «похоже», «в этой ситуации».
- Не ставить диагнозы и не приписывать намерения.
- Не оценивать людей как «хороших/плохих», только динамику пары.
- Не повторять одну мысль разными словами ради объёма.
- Астрологические термины допустимы только в optional `technical_basis`, который не показывается в основном UX.

### Рекомендуемый контракт отчёта

```json
{
  "pair_summary": {
    "score": 0,
    "label": "Очень легко",
    "headline": "Вы быстро становитесь командой",
    "summary": "2–3 коротких предложения",
    "tags": ["Общий темп", "Живая химия", "Лёгкий старт"],
    "precision": "exact | approximate"
  },
  "contexts": {
    "love": {
      "score": 0,
      "strengths": [],
      "frictions": [],
      "repairs": []
    },
    "home": {},
    "work": {},
    "travel": {}
  },
  "technical_basis": {
    "factors": [],
    "model_notes": []
  }
}
```

## UX решения, которые нужно сохранить при реализации

- Сначала беглый обзор, потом глубина.
- Один экран — одна задача; никакой длинной статьи сразу после заголовка.
- Баллы переключаются по сфере и пересортировывают список кандидатов.
- Неизвестное время рождения явно снижает точность.
- Проверка «совпало / частично / не похоже» привязана к паре и выбранной сфере.
- Техническая астрология не конкурирует с человеческим выводом.
