# Wave 09 — Corrective Frontend Migration Audit

> Role: implementer/auditor. Do not change production UI code in this wave.

## Goal

Stop the incorrect frontend migration before more code is layered on top of it. Build a factual migration audit that decides what must be kept, removed, or re-ported from the real visual oracle.

## Root Cause

The previous migration waves were reviewed against internal mock fixtures and local assumptions, but the real visual oracle is the running mock-preview app:

- Repo/path: `/opt/solarsage-astro-mock-preview`
- Branch: `archive/demo-origin-main`
- Known commit: `19d7db9`
- Runtime port: `3001`

Current production/dev app:

- Repo/path: `/opt/solarsage-astro`
- Branch: `main`
- Current known commit: `6990588`
- Runtime port: `3002`
- Pre-migration baseline: `ebda0c1`

The visible `/day` screen in Telegram differs sharply from the 3001 oracle. Treat this as a migration-quality failure, not as a styling bug.

## Non-Negotiable Constraints

- Do not edit app/runtime code in this wave.
- Do not run destructive git operations.
- Do not `git reset --hard`.
- Do not force push.
- Do not merge or cherry-pick whole branches.
- Do not copy runtime mocks into production code.
- Do not copy static/demo astrology into production code.
- Production UI may consume only real API data, existing real adapters, or explicitly documented new backend/API contracts.
- E2E mock fixtures may exist only under test-only paths such as `e2e/mock-visual/**`.
- If a 3001 visual block depends on mock-only astrology data, classify it as one of:
  - `PORT_UI_HIDE_UNTIL_CONTRACT`
  - `PORT_UI_WITH_EXISTING_REAL_DATA`
  - `REQUIRES_BACKEND_CONTRACT`
  - `DO_NOT_PORT_DEMO_ONLY`
