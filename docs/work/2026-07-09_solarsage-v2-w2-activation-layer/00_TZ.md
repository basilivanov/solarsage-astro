## Required Implementation

### 1. API `ActivationLayerService`

Create:

```text
apps/api/app/services/activation_layer_service.py
apps/api/tests/test_activation_layer_contract.py
apps/api/tests/fixtures/activation_layer_minimal.json
```

Implement:

```python
class ActivationLayerService:
    def build(
        self,
        *,
        natal_context: dict,
        transits: dict,
        day_signals: list[AstroSignal],
        target_date: date,
        target_time: str,
        target_tz: str,
        house_system: str,
        sidecar_activation_layer: ActivationLayer | dict | None = None,
    ) -> ActivationLayer:
        ...
```

Rules:

- If `sidecar_activation_layer` is provided, validate it with API `ActivationLayer` and return it.
- If no sidecar layer is provided, build a minimal layer from `day_signals`.
- Use `day_signals` only, not all normalized signals; static natal background must not become activations.
- Generate only these W2 minimal activations:
  - transit aspect to natal planet;
  - transit planet in natal house.
- Do not generate profection, firdar, solar/lunar return, progression, solar arc, lot, angle, or eclipse activations in W2.

Activation mapping:

- Transit aspect:
  - source signal: `AstroSignal(type="aspect", planet="Transit_*", target_planet=...)`;
  - `technique="transit_to_natal"`;
  - `technique_family="transit"`;
  - `target_type="planet"`;
  - `target_key=<clean uppercase target planet>`;
  - `source_planet=<clean uppercase transit planet>`;
  - `source_frame="transit"`;
  - `target_planet=<clean uppercase natal planet>`;
  - `target_frame="natal"`;
  - `aspect=<signal.aspect_type>`;
  - `orb=<signal.orb>`;
  - `strength=<signal.strength>`;
  - `phase=<signal.phase or "background">`;
  - polarity: `trine/sextile -> supportive`, `square/opposition -> tense`, `conjunction -> mixed`, otherwise `neutral`;
  - evidence string must explicitly say transit-to-natal, e.g. `Transit Moon opposition natal Pluto, orb 1.0454°`.
- Transit planet in natal house:
  - source signal: `AstroSignal(type="planet_in_house", planet="Transit_*", house=...)`;
  - `technique="transit_planet_in_house"`;
  - `technique_family="transit"`;
  - `target_type="house"`;
  - `target_key=<house number as string>`;
  - `source_planet=<clean uppercase transit planet>`;
  - `source_frame="transit"`;
  - `house=<house number>`;
  - `strength=<signal.strength>`;
  - `polarity="neutral"`;
  - evidence string must say the transit planet is in natal house N.

Index maps:

- `by_planet` must index planet-target activations by uppercase clean target planet.
- `by_house` must index house activations by string house number.
- `by_lot` and `by_angle` must remain `{}` in W2 unless sidecar layer provides valid entries.
- Never duplicate activation objects inside index maps; ids only.
- Ids must be deterministic and stable across runs for the same user/date/signals.

Canon:

- Because W2 introduces `transit_planet_in_house`, update `grace/canon/activation_rules.v1.yml` and `apps/api/app/services/canon_service.py` known-technique validation so this is a recognized `transit` technique.
- Keep canon version strings at `v1`.
