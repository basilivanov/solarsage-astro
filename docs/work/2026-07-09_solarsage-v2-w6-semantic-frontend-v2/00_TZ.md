### 2. Backend deterministic V2 semantic builder

Create:

```text
apps/api/app/services/semantic_v2_service.py
apps/api/tests/test_semantic_v2_service.py
```

Responsibilities:

- Build `TodayV2Block` from:
  - `activation_layer`;
  - optional `ScoringV2Result` from `DayScoringRuntimeService`;
  - optional V1/V2 diff;
  - selected meta/version fields.
- Use `activation_layer.activations[]` as source of truth.
- `activationSummary.topActivatedTargets` groups activations by target and counts unique `technique_family`.
- Sort top targets deterministically:
  1. descending `family_count`;
  2. descending total activation strength;
  3. `target_type`;
  4. `target_key`.
- Build Russian/user-facing labels for common planets/houses/lots/angles. Keep exact technical strings in `activationEvidence.evidence`.
- `whyToday` must be deterministic. No LLM. It should reference real activation ids and technique names only.
- If there is no convergence, return a clear deterministic fallback:
  `День в основном определяется текущими транзитами, без сильной сходимости долгих техник.`
- `scoreBreakdown` must be populated from `ScoringV2Result.sphere_scores` when V2 result exists; otherwise `{}`.
- Provide a deterministic helper that returns activation/contribution evidence for a backend sphere key. `TodayInterpretationService` will use this helper to enrich row evidence.

Do not duplicate Scoring V2 math inside this service.

### 4. LLM claim validator

Create:

```text
apps/api/app/services/llm_claim_validator.py
apps/api/tests/test_llm_claim_validator.py
```

Minimum deterministic API:

```python
class LLMClaimValidator:
    def validate_concrete_advice_text(
        self,
        *,
        row_key: str,
        verdict: str,
        text: str,
        evidence: list[ConcreteAdviceEvidence],
    ) -> str | None:
        ...
```

Return:

- original text when supported and safe;
- deterministic replacement text when unsafe/contradictory;
- `None` only if caller should reject the text.

Hard guards required by doc-15:

| Row/verdict | Must reject or replace |
|---|---|
| relationships + avoid | direct relationship improvement / conflict-opening advice |
| money + avoid | invest/spend/buy recommendation |
| health/body/sport + avoid | intense sport recommendation |
| communication + avoid | hard negotiation recommendation |

Allowed mitigation style:

```text
Если контакт неизбежен, выбирай короткий спокойный формат и не разбирай острые темы.
```

Integrate it after LLM concrete-advice generation and before assigning `ConcreteAdviceRow.text`. Existing `validate_row_text()` can remain, but the new validator must be called and covered by tests.

### 5. LLM prompt evidence packet

Modify:

```text

```

For concrete advice and why sections, ensure prompts include an evidence-packet style contract. Prefer adding one deterministic builder in `semantic_v2_service.py` instead of assembling unrelated dicts independently in each caller:

```json
{
  "day_status": "...",
  "status_breakdown": {},
  "top_activations": [],
  "sphere_scores": {},
  "concrete_rows": [],
  "forbidden_claims": [],
  "required_distinctions": [
    "distinguish transit-to-natal from transit-to-transit"
  ]
}
```

Do not overbuild an NLP parser. The key is that LLM receives explicit evidence and forbidden claims; deterministic validator enforces hard guards.

The `forbidden_claims` list must be derived from row verdicts, not hardcoded globally. The packet's activation facts must come from `ActivationLayer`/`ScoringV2Result`, never from LLM output.
