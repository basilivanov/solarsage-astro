### 3. Root-cause each failure before fixing

For each failure, write a short root-cause note in the report before applying a fix.

Required classifications:

- `product_bug`
- `test_bug`
- `test_race`
- `environmental`
- `not_reproduced`
- `blocked_needs_architecture`

Known failure details to investigate:

1. Onboarding network error test:
   - Test: `edge-cases.spec.ts >> Onboarding — Validation >> should handle network error during profile save (graceful)`.
   - Artifact shows the page reached the done screen and rendered `Load failed`, not the expected profile-save error.
   - Investigate whether `page.route('**/api/profile', route => route.abort())` catches the actual `PUT /api/profile` request.
   - If the app really navigates after failed profile save, fix product code.
   - If the route interception is registered too late or misses the URL shape, fix the test.

2. Calendar day click test:
   - Test: `edge-cases.spec.ts >> Calendar >> should navigate to day on click`.
   - Artifact shows the click happened while URL stayed `/calendar`.
   - Current UI has separate day selection and `Открыть день` summary CTA.
   - Investigate accepted behavior: if grid tap should only select and CTA opens the day, update the test to assert selection then click the CTA. If grid tap is supposed to open the day directly, fix product code.
   - Do not make the test click a disabled day.

3. Reset done-state test:
   - Test: `edge-cases.spec.ts >> Reset >> should load reset page and show done state`.
   - Artifact shows `Готово` was visible but the test timed out.
   - Investigate whether timeout is caused by pending network, selector ambiguity, browser close, or a test waiting pattern.
   - Prefer `getByText(...).toBeVisible()` / `getByRole(...)` and state-based waits over fixed sleeps.

4. Readings TabBar test:
   - Test: `locked-features.spec.ts >> Locked Features >> /readings page shows Спросить in TabBar`.
   - Artifact shows `page.goto('/readings')` was interrupted by another navigation to `/day/today`.
   - `app/(grace)/page.tsx` intentionally redirects `/` to `/day/today`; the test currently visits `/` before `/readings`.
   - Investigate if this is a test race. If yes, remove the unnecessary `/` navigation or wait for the first redirect to settle before navigating to `/readings`.
   - Do not change product routing just to satisfy this test.

5. Mock-visual calendar channel-closed artifact:
   - Test: `mock-visual/calendar.spec.ts >> calendar screen renders in ready state with month header, grid, lunar strip, and summary`.
   - Required mock-visual mobile gate passed in Wave 07; this artifact appeared during the optional full mobile run.
   - Rerun in isolation. If it passes twice, classify as environmental/transient and record evidence.
   - If it fails reproducibly, fix the root cause without weakening mock-visual route interception.

### 4. Implement minimal fixes

Allowed changes:

- `e2e/*.spec.ts`, if root cause is stale expectation, route timing, or test race.
- `e2e/fixtures.ts` or `playwright.config.ts`, only if root cause is shared test infrastructure.
- Product UI files, only if root cause is actual user-facing broken behavior.
- New unit/component tests, only if product code changes need faster coverage.

Required coding rules:

- Keep semantic/test contracts useful: prefer `getByRole`, `getByTestId`, stable accessible names, `toHaveURL`, and explicit `data-*` state assertions.
- Preserve real Telegram auth in non-mock e2e.
- Preserve mock route interception only inside `e2e/mock-visual`.
- Do not add broad catch-all request mocking to full e2e.
