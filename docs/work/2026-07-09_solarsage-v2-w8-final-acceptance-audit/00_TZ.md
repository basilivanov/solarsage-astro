## Audit Method

Create a requirement-by-requirement matrix.

For every checklist item below, set exactly one status:

- `PROVEN`: current evidence directly proves the requirement.
- `GAP`: current evidence contradicts the requirement or the requirement is not implemented.
- `WEAK`: there is some evidence, but it is indirect or too narrow for the requirement.
- `MISSING`: no evidence found.

Each row must include:

- requirement text;
- status;
- authoritative evidence;
- command output or file path/line references;
- notes/risk;
- recommended next action if not `PROVEN`.

Do not mark `PROVEN` based only on an old acceptance doc. Acceptance docs are useful pointers, but final proof must include current code, current tests, current artifacts, or fresh command output.
