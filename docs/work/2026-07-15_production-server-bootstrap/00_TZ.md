# ТЗ — канонический production deployment для `astro.vasiliy-ivanov.ru`

Дата: 2026-07-15

Исполнитель: кодер в `tmux astro:0.0`.

Роль архитектора: постановка, review, секреты и фактический rollout на удалённый сервер. Кодер не получает и не выводит реальные credentials.

## 1. Контекст и цель

```text

```

Его token запрещено писать в repository, docs, tests, shell scripts, workflow YAML или handoff.

Цель change-set:

1. Создать однозначный production runtime contract без legacy port drift.
2. Оставить PostgreSQL в Docker, а API/sidecar/frontend — в systemd, как в каноническом runtime.
3. Добавить воспроизводимый manual deployment script.
4. Добавить manual-only GitHub Actions production deployment для будущего private repository.
5. Снизить расход GitHub private-repo minutes без ослабления PR quality gate.
6. Добавить backup/restore runbook.

## 4. New production DB compose

Create:

```text
infra/production/docker-compose.yml
```

Requirements:

- GRACE `AI_HEADER`, module contract/map comments appropriate for YAML;
- Compose project name `solarsage-prod`;
- only one service: `db`;
- image `postgres:15` (production stays on the currently proven major 15; no implicit major upgrade);
- `container_name: solarsage-db`;
- `restart: unless-stopped`;

- host bind exactly `127.0.0.1:5433:5432`, never `0.0.0.0`;
- named volume `solarsage_postgres_data`;
- healthcheck uses `pg_isready` and container env without expanding secrets into compose output;
- `security_opt: [no-new-privileges:true]`;
- reasonable `stop_grace_period` and `shm_size`;
- no plaintext values and no default password.

Expected operator command:

```bash
docker compose \
  --env-file /opt/solarsage-astro/.env.production \
  -f /opt/solarsage-astro/infra/production/docker-compose.yml \
  up -d db
```

## 5. Canonical systemd units

Create/replace repository templates:

```text
infra/systemd/solarsage-api.service
infra/systemd/solarsage-sidecar.service
infra/systemd/solarsage-frontend.service
```

### 5.1 API

Contract:

```text
User/Group: astro
WorkingDirectory: /opt/solarsage-astro/apps/api
EnvironmentFile: /opt/solarsage-astro/.env.production
PATH: apps/api/.venv/bin + system paths
ExecStart: apps/api/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart: on-failure
```

Add safe systemd hardening that does not break the app:

- `NoNewPrivileges=true`;
- `PrivateTmp=true`;
- `ProtectHome=true`;
- `ProtectSystem=full` (not strict unless verified against runtime writes);
- explicit graceful stop timeout;
- journal stdout/stderr;
- `UMask=0027`.

Do not add multiple uvicorn workers yet: in-memory singleton/task behavior and DB pool sizing have not been audited for multi-worker production.

### 5.2 Sidecar

Contract:

```text
User/Group: astro
WorkingDirectory: /opt/solarsage-astro/apps/solarsage
EnvironmentFile: /opt/solarsage-astro/.env.production
PYTHONPATH: /opt/solarsage-astro/apps/solarsage
ExecStart: apps/solarsage/venv/bin/uvicorn solarsage.app:app --host 127.0.0.1 --port 18091
Restart: on-failure
```

Use the same safe hardening subset. Sidecar is loopback-only and has no public Nginx route.

### 5.3 Frontend

Contract:

```text
User/Group: astro
WorkingDirectory: /opt/solarsage-astro
NODE_ENV=production
PORT=3002
HOSTNAME=127.0.0.1
NEXT_TELEMETRY_DISABLED=1
ExecStart: node node_modules/next/dist/bin/next start -H 127.0.0.1 -p 3002
Restart: on-failure
```

Frontend unit must not run `pnpm build` in `ExecStartPre`. Build belongs to deploy phase so a restart cannot unexpectedly rebuild or fail after a reboot.

## 6. Backup automation

Create:

```text
scripts/prod-backup.sh
infra/systemd/solarsage-backup.service
infra/systemd/solarsage-backup.timer
```

Script requirements:

- `set -euo pipefail`, `umask 077`;
- source `/opt/solarsage-astro/.env.production` without printing it;
- `pg_dump` against `127.0.0.1:5433` in custom format;
- output `/var/backups/solarsage/db-UTC_TIMESTAMP.dump`;
- create a checksum file;
- retention 14 days;
- never echo password/token/provider keys;
- fail non-zero if dump or checksum fails;
- no Redis backup.

Timer:

- daily around 03:20 local server time;
- `Persistent=true`;
- randomized delay up to 15 minutes;
- service runs as `astro`;
- `/var/backups/solarsage` will be provisioned with `astro:astro`, mode `0700` during rollout.

## 7. Production Nginx config

Create:

```text
infra/nginx/astro.vasiliy-ivanov.ru.conf
```

This is the final TLS config after Certbot certificate issuance.

Requirements:

- `server_name astro.vasiliy-ivanov.ru` only;
- port 80 redirects to HTTPS except ACME challenge path;
- port 443 TLS paths:

  ```text
  /etc/letsencrypt/live/astro.vasiliy-ivanov.ru/fullchain.pem
  /etc/letsencrypt/live/astro.vasiliy-ivanov.ru/privkey.pem
  ```

- include standard Certbot SSL options if present;
- `/api/` -> `http://127.0.0.1:8000`;
- `/` -> `http://127.0.0.1:3002`;
- preserve Host, real IP, forwarded headers and cookies;
- API read/send timeout 300s because LLM generation may be slow;
- frontend websocket upgrade headers;
- `client_max_body_size 5m`;
- block dotfiles except `/.well-known/acme-challenge/`;
- add safe headers: `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS on TLS server;
- do not add a speculative CSP that could break Telegram WebApp SDK/runtime;
- no references to dev/test domains or ports 8001/3000/3003.

Avoid dependency on an undefined `$connection_upgrade` map. Use a self-contained header strategy.

## 8. Manual deployment script

Create:

```text
scripts/prod-deploy.sh
```

Purpose: one reproducible deployment entry point. It must support:

```bash
scripts/prod-deploy.sh --current
```

for the architect's initial bundle/bootstrap checkout, and:

```bash
scripts/prod-deploy.sh
```

for future `origin/main` deployments.

Required behavior:

1. `set -euo pipefail`, `umask 027`.
2. Refuse root execution; expected user is `astro`.
3. Acquire a non-blocking `flock` lock so two deploys cannot overlap.
4. `cd /opt/solarsage-astro` and require `.env.production` mode no broader than `0640`.
5. `--current`:
   - do not fetch/switch refs;
   - require tracked worktree clean;
   - deploy current HEAD.
6. Default mode:
   - `git fetch --prune origin main`;
   - resolve exact `origin/main` SHA;
   - require clean tracked worktree;
   - checkout detached exact target SHA or fast-forward a dedicated production branch without merge commits;
   - print only SHA, never remote credentials.
7. Read/export `.env.production` without printing it.
8. Fail-closed preflight using real environment:
   - import `app.main`/runtime policy;
   - assert canonical production environment;
   - assert `APP_DOMAIN=astro.vasiliy-ivanov.ru`;
   - assert `DEV_MODE=false`, secure cookie, non-SQLite DB and expected bot username if the latter is not part of API settings;
   - never print token/key values.
9. Dependency/build order:
   - `pnpm install --frozen-lockfile`;
   - `pnpm guardrails:prod`;
   - create/reuse `apps/api/.venv`, upgrade pip/wheel, install local `packages/py-contracts`, then `apps/api` without dev extras;
   - create/reuse `apps/solarsage/venv`, install local `packages/py-contracts`, then `apps/solarsage` without dev extras;
   - `NODE_ENV=production APP_ENV=production pnpm build`;
10. DB safety:
   - run `scripts/prod-backup.sh` before Alembic if DB is reachable and initialized;
   - run `apps/api/.venv/bin/alembic -c apps/api/alembic.ini upgrade head` from a working directory that imports `app` correctly;
   - print current Alembic head(s), not credentials.
11. Restart order:
   - sidecar, wait for `http://127.0.0.1:18091/v1/health`;
   - API, wait for `http://127.0.0.1:8000/api/health`;
   - frontend, wait for `http://127.0.0.1:3002/`;
12. Final HTTPS smoke if Nginx/certificate exist.
13. Print deployed SHA and concise PASS/FAIL summary.

Use bounded retry loops, not fixed long sleep. Do not automatically clear caches or downgrade migrations. Do not log the environment.

If automatic rollback is not migration-safe, do not pretend otherwise. Fail and leave an explicit operator message with old/target SHA.

## 9. GitHub Actions for private repository and 2000-minute budget

### 9.1 Existing CI

Modify:

```text
.github/workflows/ci.yml
```

Policy:

- private repository checkout continues to use repository-scoped `GITHUB_TOKEN`; no PAT is required in checkout;
- trigger quality CI on PR to `main` and `workflow_dispatch`;
- remove duplicate `push: main` run so a merged PR does not pay for the same full suite twice;
- add concurrency per PR/ref with `cancel-in-progress: true`;
- remove the Playwright E2E job from general CI; E2E remains manual in its dedicated workflow;
- retain backend, sidecar, frontend, contract and guardrail coverage;
- prefer pnpm and `pnpm-lock.yaml`, not `npm install`;
- enable official setup-node/setup-python caches where valid;
- update no unrelated test commands.

Do not aggressively combine all jobs unless dependency/install semantics are verified. Predictability is more important than a speculative minute saving.

### 9.2 E2E and visual workflows

`e2e.yml` is already manual-only. Keep it manual-only; update only obviously stale action major versions/pnpm/Python version if needed for syntax/runtime consistency. Do not turn it into an automatic production gate in this wave.

Change `visual-regression.yml` to `workflow_dispatch` only, update official actions from deprecated v3 to v4/current majors already used elsewhere, pnpm install/build, and correct the port command if required. It must not consume minutes on every PR.

### 9.3 Production deploy workflow

Create:

```text
.github/workflows/deploy-production.yml
```

Requirements:

- manual `workflow_dispatch` only for now;
- `permissions: contents: read`;
- `environment: production`;
- concurrency group `production-deploy`, `cancel-in-progress: false`;
- no third-party SSH action;
- install private key from environment secret into an ephemeral `~/.ssh` file with mode `0600`;
- use pinned known_hosts from secret, never `StrictHostKeyChecking=no`;
- connect to `${PROD_USER}@${PROD_HOST}`; server-side forced command owns the deploy operation;
- no secret echo;
- always remove ephemeral key in a final cleanup step.

Expected GitHub environment secrets (names only):

```text
PROD_HOST
PROD_USER
PROD_SSH_PRIVATE_KEY
PROD_KNOWN_HOSTS
```

Do not add actual values to YAML/docs.
