## 1. Исправить byte-exact comparison

Текущая реализация использует:

```bash
expected=$(cat << 'EOF'
...
EOF
)
actual=$(cat "$file")
[ "$actual" = "$expected" ]
```

Это не является full-content equality: command substitution удаляет все trailing newline. Поэтому файл без финального newline или с лишними пустыми строками ошибочно принимается как exact generated форма.

Заменить сравнение на побайтовое. Предпочтительный минимальный вариант для Bash — `cmp -s` с process substitution и `printf '%s\n'` для каждой exact строки. Эталон обязан содержать ровно один финальный newline и ровно такой текст:

```ts
/// <reference types="next" />
/// <reference types="next/image-types/global" />
import "./.next-prod/types/routes.d.ts";

// NOTE: This file should not be edited
// see https://nextjs.org/docs/app/api-reference/config/typescript for more information.
```

Не использовать command substitution для самого сравниваемого содержимого, не нормализовать whitespace/newline, не использовать grep и не создавать tracked fixture-файл. Если добавляется `cmp`, добавить его в dependency comment в header.

Сохранить разрешённую restore-команду без изменений:

```bash
git restore --source=HEAD --worktree -- next-env.d.ts
```

## 2. Исправить function contract и stage

`cleanup_post_build` реально пишет safe informational/error logs, поэтому `emitted_logs: none` неверен. Исправить contract на фактическое поведение без раздутого описания.

Перед вызовом helper после `pnpm build` установить отдельный:

```bash
STAGE="post-build-cleanup"
```

чтобы failure handler не сообщал ошибочно `frontend-build`, когда сама сборка уже завершилась.

## 3. Исправить Markdown-нумерацию runbook

В `docs/PRODUCTION_RUNBOOK.md` строки блока установки sudoers и пункт `4. Harden User Permissions` сейчас имеют лишние пробелы. Из-за этого пункт 4 может рендериться вложенным в пункт 3, а команды получают лишний leading space.

Сделать единообразно с пунктами 1, 2, 5:

- содержимое fenced code block — три пробела от начала списка, без дополнительного пробела внутри команд;
- closing fence на той же глубине;
- `4. **Harden User Permissions:**` начинается с первой колонки;
- его continuation line имеет три пробела.

Смысл текста и команды не менять.

## 4. Уточнить wrapper module map

В `infra/production/solarsage-github-deploy` semantic block всё ещё описан только как validation `SSH_ORIGINAL_COMMAND`, хотя теперь проверяет и positional arguments. Обновить только этот comment, runtime logic не менять.

Повторить прежние три R6 regression-сценария и добавить два отрицательных exactness-сценария во временном git repo/harness:

1. exact generated bytes с одним финальным newline -> restore к HEAD, exit 0, tracked clean;

4. exact text без финального newline -> non-zero, файл сохранён;
5. exact text с дополнительным trailing newline -> non-zero, файл сохранён.

Также повторить обе безопасные wrapper regression R5A. Никогда не вызывать wrapper одновременно с пустым `SSH_ORIGINAL_COMMAND` и нулём arguments.
