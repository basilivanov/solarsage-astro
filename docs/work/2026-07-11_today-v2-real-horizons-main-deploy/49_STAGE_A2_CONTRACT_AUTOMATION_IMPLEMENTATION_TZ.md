## 5. Compatibility checker

Создать `scripts/contracts/check_compat.py` только на stdlib, с полным GRACE
header/map и function contracts для parsing, normalization, comparison, report
и CLI.

### 5.1 CLI

```text
--base-ref REF
--current PATH
--json-output PATH
--json
--allow-breaking
```

Defaults:

```text
current = packages/contracts/openapi.json
base priority:
1. --base-ref
2. CONTRACT_BASE_REF
3. git merge-base HEAD origin/main
```

Ref verify через subprocess list arguments, без `shell=True`. Base JSON читать
только через:

```text
git show <verified-commit>:packages/contracts/openapi.json
```

Если ref/origin/main недоступен: exit `2`, сообщение с
`git fetch origin main`; не fallback к HEAD и не silent skip.

Exit contract:

```text
0 = no-change/additive
1 = breaking без approved override
2 = ref/input/JSON/config error
```

`--allow-breaking` работает только при non-empty
`CONTRACT_BREAKING_REASON.strip()`, иначе exit `2`. CI override не использует.

### 5.2 JSON/human report

Deterministic JSON, sorted keys, trailing newline:

```json
{
  "reportVersion": "solarsage.contract-compat.v1",
  "baseRef": "<resolved commit>",
  "currentArtifact": "packages/contracts/openapi.json",
  "classification": "no-change|additive|breaking",
  "changedSchemas": [],
  "additiveChanges": [],
  "breakingChanges": [],
  "informationalChanges": [],
  "overrideUsed": false
}
```

Change item содержит только `kind`, `path`, `reason`. Arrays сортируются по
`(path, kind, reason)`. Full schema fragments/fixtures не выводить.

Default stdout — concise human summary. `--json` выводит только JSON.
`--json-output` пишет JSON в указанный temp path и сохраняет human stdout.

### 5.3 Scope and ignored annotations

Сравнивать `paths` и `components.schemas`.

Documentation-only, не влияет на classification:

```text
title
description
example/examples
x-*
```

Не использовать whole-document equality как единственный алгоритм.

### 5.4 Additive

- endpoint/method/schema component added;
- optional property added;
- required -> optional;
- enum widened;
- nullability widened;
- anyOf/oneOf variant added;
- constraint loosened;
- `additionalProperties false -> true/absent`;
- known wire version monotonic increase без structural breaking.

### 5.5 Breaking

- endpoint/method/schema/property removed;
- optional -> required или required property added;
- primitive/container/array-items/`$ref` change;
- enum narrowed;
- nullability narrowed;
- anyOf/oneOf variant removed;
- discriminator property/mapping change;
- alias rename: removal остаётся breaking;
- constraint tightening: min increases, max decreases, minLength/minItems
  increases, maxLength/maxItems decreases, pattern changes;
- `additionalProperties true/absent -> false`;
- schema-valued additionalProperties narrows;
- non-version default changed — conservative breaking;
- known version malformed, family changed or decreased.

Если есть additive и breaking, итог `breaking`.

### 5.6 Normalization details

Nullable/union representations:

```text
type: [string, null]
anyOf/oneOf с type:null
nullable:true
```

нормализовать в deterministic variant set. Порядок variants не считается
изменением. `$ref` и array item shape входят в signature.

`additionalProperties` absence трактовать как `true`.

### 5.7 Version discipline

Known properties:

```text
schemaVersion
activationLayerVersion
calculationVersion
scoringVersion
payloadVersion
```

Formats минимум:

```text
activation-layer.vN
al-N.N
ss-calc-N.N.N
ss-scoring-N.N
today.vN
```

Monotonic increase — informational. Downgrade/malformed/family change —
breaking. Реальный `al-1.0 -> al-1.1` не должен сделать additive result
breaking.
