## 1. Модели + миграция 0023

**`election_requests`** (зеркала horary_questions, урезанная): id uuid PK; user_id FK users CASCADE index; `event_type` String(20); `window_from` Date; `window_to` Date; `status` String(20) default "pending" (pending|processing|done|failed|refunded); `client_timezone` String(64) nullable; `spent_credit_id` FK horary_credits nullable; `refund_status` String(20) default "none" (none|refunded|not_refundable); `failure_stage/code/message` String nullable; `public_error_code/message` String nullable; `idempotency_key` String(80) (UniqueConstraint с user_id); `request_hash` String(64); `created_at`, `updated_at` (timestamptz, now).

**`election_results`**: id uuid PK; `request_id` FK election_requests CASCADE **unique**; `payload_json` Text (JSON: {event, best_days, avoid_days}); `created_at`.

**`election_credit_spends`** (зеркала horary_credit_spends): id uuid PK; `credit_id` FK horary_credits CASCADE index; `election_request_id` FK election_requests CASCADE **unique**; `amount` Integer default 1 CHECK amount=1; `idempotency_key` String(80) unique; `created_at`.

## 2. Сервис — `apps/api/app/services/election_service.py`

GRACE-шапка. Методы:
- `create_search(user_id, event_type, window_from, window_to, idempotency_key, client_timezone) -> ElectionRequest` — валидация event_type по канону, окно ≤ 62 дней и from ≤ to, request_hash = sha256(f"{user_id}|{event_type}|{window_from}|{window_to}"). Идемпотентность по (user_id, idempotency_key): существующая запись с тем же request_hash → вернуть её (200-семантика), с другим хэшем → 409 IDEMPOTENCY_CONFLICT. Атомарно: `HoraryCreditService.select_spendable_credit` + `used_amount += 1` + вставка election_credit_spends + вставка election_requests(status="pending") — одна транзакция (паттерн `spend_credit_for_question`). Нет кредитов → 402 NO_HORARY_CREDITS (тот же код, общий кошелёк).
- `run_search_task(request_id)` — фоновая: status=processing → sidecar `lunar_window` → `election_engine.scan` → вставка election_results + status=done. Любая ошибка → status=failed + failure_* + public_error_* + refund (удалить spend-строку, `used_amount -= 1`, refund_status=refunded, status=refunded) — паттерн из horary_service.
- `get_quota(user_id)` — прокси к `HoraryCreditService.get_balance` (общий кошелёк — тот же HoraryQuotaRead).
- `list_searches(user_id, limit, offset)`, `get_search(user_id, request_id)` — с подгрузкой result.

## 3. API — `apps/api/app/api/election.py`

Зеркала horary.py (роутер `/api/election`, смонтировать в `main.py` рядом с horary):
- `GET /quota` → HoraryQuotaRead (переиспользовать схему horary).
- `POST /searches` → 201 ElectionSearchRead. Body: `{event_type, window_from, window_to, idempotency_key, client_timezone?}` (pydantic-схема в `app/schemas/election.py`, camelCase через CamelModel как у horary). После коммита — `asyncio.create_task(service.run_search_task(request.id))`.
- `GET /searches?limit&offset` → list[ElectionSearchRead]
- `GET /searches/{id}` → ElectionSearchRead (+result payload при done; 404 чужой/нет)

`ElectionSearchRead`: id, event_type, window_from, window_to, status, created_at, result (nullable {best_days, avoid_days}), public_error_code/message (nullable). События логов (добавить во ВСЕ ТРИ реестра — observability.xml §8.5, logging_events.py, events.gen.ts; owner="W-ELECTION"): `election.search_created`, `election.search_succeeded`, `election.search_failed`, `election.credit_refunded`.
