## Architecture Decisions

### Ownership

Firdar calculation belongs in the sidecar activation layer path.

API remains a validator/merger for sidecar activation layers in W3.3. API must not independently calculate Firdar periods in this wave.

### No Hidden Constants

Do not bury Firdar sequence/year constants directly in application logic.

Create a sidecar-loaded canon file:

```text
grace/canon/firdar.v1.yml
```

The sidecar implementation must load this canon at runtime/test time. If canon keys are missing, fail clearly in tests/dev rather than silently falling back.

Suggested structure:


### Sect / Day-Night

Use the same sidecar sect logic already used by activation builder:

```text
is_day_birth = Sun in houses 7..12
```

Reuse or extract the existing `_is_day_chart(natal_sun_house)` behavior. Do not create a second incompatible day/night rule in W3.3.

### Age Basis

Calculate Firdar age from local dates:

```text
age_years = completed_years + elapsed_days_since_last_birthday / days_in_current_birthday_year
```

Use the request's local `birth_date` and local `target_date` as calendar dates, same philosophy as W3.2 profections. Do not convert the date across UTC boundaries for this period calculation.

Boundary rule:

```text
start_age <= age_years < end_age
```

At an exact period boundary, the next period starts.

If age is `>= cycle_years`, use deterministic modulo cycle handling:

```text
cycle_age = age_years % 75
cycle_index = floor(age_years / 75)
```

Emit these in debug. This avoids undefined behavior for users older than 75 without changing the period contract.

### Minor Subperiod

For the seven planetary major periods, split the major period into `minor_divisions=7` equal subperiods.

The minor sequence rotates from the active major lord over the seven-planet day/night sequence:

```text
day planets:   SUN, VENUS, MERCURY, MOON, SATURN, JUPITER, MARS
night planets: MOON, SATURN, JUPITER, MARS, SUN, VENUS, MERCURY
```

Examples from existing fixtures:

```text

night MOON major   -> MOON, SATURN, JUPITER, MARS, SUN, VENUS, MERCURY

```

For node major periods, use `node_minor_sequence` from canon.

## Activation Shape

Generate exactly two Firdar activations for the active date:

```text
firdar_major planet: major_period_lord
firdar_minor planet: minor_period_lord
```

Required fields:

- `technique`: `firdar_major` or `firdar_minor`
- `technique_family`: `firdar`
- `target_type`: `planet`
- `target_key`: uppercase lord key (`SUN`, `SATURN`, `NORTH_NODE_TRUE`, etc.)
- `kind`: `major_period_lord` or `minor_period_lord`
- `phase`: `period`
- `polarity`: `neutral`
- `strength`: from `grace/canon/activation_rules.v1.yml`
  - `firdar_major: 0.65`
  - `firdar_minor: 0.40`
- `target_planet`: same uppercase lord key
- `source_frame`: `natal`
- `target_frame`: `natal`
- `evidence`: deterministic, not LLM text
- `debug`: period calculation evidence

Stable id examples for Basil `2026-07-08`:

```text
firdar_major__PERIOD_LORD__SUN
firdar_minor__SUBPERIOD_LORD__SATURN
```

Index requirements:

- both Firdar activations must be referenced in `by_planet[PLANET]`;
- all index refs must point to an existing `activations[].id`;
- both activations must use `technique_family="firdar"` so W4 convergence can dedupe them as one family.

Evidence examples:

```text
Sun is major firdar lord on 2026-07-08
Saturn is minor firdar lord on 2026-07-08 within Sun major firdar
```

Debug requirements:

```json
{
  "schema_version": "firdar.v1",
  "is_day_birth": false,
  "sect_basis": "sun_house",
  "sun_house": 5,
  "birth_local_date": "1980-10-30",
  "target_local_date": "2026-07-08",
  "age_years": 45.68767123287671,
  "cycle_age": 45.68767123287671,
  "cycle_index": 0,
  "cycle_years": 75,
  "major_lord": "SUN",
  "major_start_age": 39,
  "major_end_age": 49,
  "major_years": 10,
  "minor_lord": "SATURN",
  "minor_index": 4,
  "minor_start_age": 44.714285714285715,
  "minor_end_age": 46.142857142857146,
  "minor_sequence": ["SUN", "VENUS", "MERCURY", "MOON", "SATURN", "JUPITER", "MARS"]
}
```

Use the relevant subset per activation, but keep enough data to audit the selected lord.
