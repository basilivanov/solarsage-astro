## Контекст

Backend готов (в main): `POST /api/election/searches` (201, camelCase: eventType, windowFrom, windowTo, idempotencyKey, clientTimezone?), `GET /api/election/searches?limit&offset`, `GET /api/election/searches/{id}`, `GET /api/election/quota` (формат = HoraryQuotaRead). Result при status=done: `{event, best_days: [{date, score, label, reasons[]}], avoid_days: [...]}` (label: great|good|ok|avoid). Продукт `election_1` (50₽, one_time) уже в каталоге → `GET /api/payment/products`.

Зеркалить UX-паттерн хорара (components/readings/horary/*): тот же poll-chain, states, data-testid контракт по AGENTS.md. Типы событий (chips, из `grace/canon/election_rules.v1.yml`):

## Файлы

### 1. Контракты и API-клиент
- `lib/contracts/election.ts` — zod-схемы ElectionSearch/Result (по образцу `lib/contracts/horary.ts`), события как const-массив с key/label/emoji (выше).
- `lib/api/election.ts` — клиент getQuota/listSearches/createSearch/getSearch (по образцу `lib/api/horary.ts`; idempotencyKey = crypto.randomUUID() на создание формы).
- `lib/api/payment.ts` — добавить `"election_1"` в union `OneTimeProductSlug` (строка ~154).

### 2. Компоненты `components/readings/election/`
- `election-screen.tsx` — root `data-testid="election-screen"`, `data-state="loading|error|ready"`, `data-has-credit`, `data-access-state="unlocked|locked"` (контракт как horary-screen). Poll после submit: немедленно + каждые 2с, кап 60с, автопереход на `/readings/election/{id}` при done.
- `election-form.tsx` — chips типов событий (single-select), **выбор окна**: пресеты «Неделя» (7д), «2 недели» (14д), «Месяц» (30д) + «Свои даты» (два date-инпута, max 62 дня — клиентская валидация). Дефолт: «2 недели» от сегодня. Submit disabled без выбранного события/окна или при отсутствии кредитов (blocked-reason как у хорара).
- `election-quota-bar.tsx` — «Доступно: N», разбивка weekly/paid/bonus (те же данные HoraryQuotaRead), кнопка «Докупить» → purchase-sheet.
- `election-purchase-sheet.tsx` — bottom-sheet: `GET /api/payment/products`, фильтр `productType==="one_time" && slug.startsWith("election_")`; startPurchase → openProviderCheckout → pollPurchaseStatus (переиспользовать `lib/billing/purchase-flow.ts` без изменений).
- `election-processing-card.tsx` — шаги: «Смотрим Луну», «Считаем фазы и курс», «Выбираем лучшие даты»; через 30с — «готовится дольше обычного».
- `election-result-view.tsx` — топ-3 карточки дат: дата + день недели RU («чт, 16 авг»), бейдж label (great «Отличный день» / good «Хороший» / ok «Нейтрально»), reasons списком. Ниже блок «Лучше не начинать»: avoid_days с reasons. Кнопка «Новый подбор» → назад к форме.
- `election-search-card.tsx` — элемент истории: emoji события, label, дата окна, статус (Считаем/Готово/Не удалось + «Списание возвращено» при refunded).
