## Часть 1. Sidecar: `POST /v1/lunar-window`

Новый эндпоинт в sidecar (файлы: `apps/solarsage/solarsage/api/lunar.py` + `apps/solarsage/solarsage/services/lunar.py` + схемы в `apps/solarsage/solarsage/schemas/` по образцу существующих).

**Request**: `{"from_date": "YYYY-MM-DD", "to_date": "YYYY-MM-DD"}` — inclusive, максимум 62 дня (больше → 422).

**Response**: `{"days": [ {...}, ... ]}` — по одному объекту на день:

```json
{
  "date": "2026-08-01",
  "moon_sign": "taurus",
  "moon_sign_ru": "Телец",
  "moon_lon_noon": 45.3,
  "phase_angle": 132.5,
  "waxing": true,
  "illumination": 0.83,
  "is_voc_noon": false,
  "voc_intervals": [{"start": "2026-08-01T14:32:00Z", "end": "2026-08-01T23:59:59Z"}],
  "voc_fraction": 0.31,
  "sign_ingress": null,
  "mercury_retro": false
}
```

Алгоритмы (pyswisseph, `swe.calc_ut`, флаги `swe.FLG_SWIEPH`):

1. **moon_lon/phase**: долготы Луны и Солнца на 12:00 UTC дня; `phase_angle = (moon_lon - sun_lon) % 360`; `waxing = phase_angle < 180`; `illumination = (1 - cos(radians(phase_angle))) / 2`.
2. **moon_sign**: `int(moon_lon // 30)` → id из списка `[aries, taurus, gemini, cancer, leo, virgo, libra, scorpio, sagittarius, capricorn, aquarius, pisces]`; `moon_sign_ru` — «Овен…Рыбы».
3. **sign_ingress**: если в этот день Луна пересекает границу знака (кратно 30°) — момент через `swe.mooncross_ut` (пример в `services/returns.py`), ISO UTC; иначе null.
4. **VOC (Луна без курса)** — определение: Луна не делает НИ ОДНОГО мажornого аспекта (conj 0°, sextile 60°, square 90°, trine 120°, opp 180°; орбы: conj 12°, opp 12°, trine 10°, square 10°, sextile 8°) к планетам Sun…Pluto до выхода из текущего знака. Реализация MVP — **шаг-скан**: по дню с шагом 5 минут (288 точек) для каждой точки определить VOC-статус (есть ли applying-аспект в пределах орба до конца знака). Переходы состояния → `voc_intervals` (слить соседние точки). `voc_fraction` = доля voc-точек. `is_voc_noon` — статус на 12:00 UTC.
5. **mercury_retro**: `speed` Меркурия на 12:00 UTC < 0.

Все вычисления чистые (без БД/сети). GRACE-шапки по AGENTS.md.

## Часть 3. Engine — `apps/api/app/services/election_engine.py`

GRACE-шапка. Детерминированный (без LLM). Публичный метод:

```python
async def scan(event_type: str, from_date: date, to_date: date, lunar_days: list[dict]) -> dict
```

- `lunar_days` — уже полученные факты из sidecar (engine НЕ ходит в сеть сам; клиент вызовет в фазе 2).
- Загружает canon `grace/canon/election_rules.v1.yml` (yaml, см. пример загрузки canon в `apps/api/app/services/` — grep `aspect_rules.v1.yml`).
- Для каждого дня считает score по формуле из canon (знак Луны preferred/disfavored/нейтральный(0), waxing, voc_fraction>threshold, mercury_retro если mercury_sensitive), clamp 0..100.
- `reasons` — список человеко-читаемых строк RU из фактов: «Луна в Тельце — стабильный фон», «Луна растущая — подходит для начинаний», «Луна без курса ~N% дня», «Меркурий ретроградный».
- Возвращает: `{"event": event_type, "best_days": [топ-3 {date, score, label, reasons}], "avoid_days": [до 3 худших {date, score, reasons}]}`, label: score≥75 `great`, ≥55 `good`, ≥35 `ok`, иначе `avoid`.
