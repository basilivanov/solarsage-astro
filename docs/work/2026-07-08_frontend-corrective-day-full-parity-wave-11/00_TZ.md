- The bottom history widget (`В этот день` / `Ближайшие дни`) must reliably render near the bottom of `/day`.

## Goal

Make `3002/main` `/day/[date]` visually and behaviorally match the 3001 `/day/[date]` frontend contract, while preserving real API/auth/data flow.

This is not a mock-data migration. It is a presentation and interaction migration over real `TodayPayload` / `adaptTodayPayload` data.

## Non-Negotiable Architecture

1. Runtime production code must not import mocks, demo fixtures, `/opt/solarsage-astro-mock-preview`, or `lib/demo-data`.
2. Keep the real data path:
   - `app/(grace)/day/[date]/page.tsx`
   - `useDay(dateStr)`
   - real `/api/day/:date`
   - `adaptTodayPayload(data, selectedDate)`
   - real calendar/lunar data where currently used
3. Do not copy static mock astrology calculations into runtime:
   - no `NATAL_HOUSES`
   - no `NATAL_PLANETS`
   - no frontend pseudo transit calculation
   - no mock moon/retrograde/planetary-day calculations unless already real/non-personal and explicitly justified
4. Copying presentation structure, styling, interaction model, and product copy patterns from `/opt/solarsage-astro-mock-preview/components/today/*` is allowed.
5. If a new UI presentation model is needed, derive it deterministically from real adapted data in `lib/adapters/today-payload.ts` or a focused display helper. Add/adjust Zod-backed UI contracts in `lib/contracts/today.ts` when data crosses component boundaries.
6. If backend fields are insufficient, prefer a small backend/API contract extension over frontend invention. Update backend schema, adapter, tests, and report why.
7. Preserve Telegram auth. Do not add product auth shortcuts.
8. Preserve canonical ports:
   - API 8000
   - frontend production 3002
   - oracle preview 3001
