# Today Human First — master-ТЗ

## Решение владельца

Внедрить рекомендованный вариант 2 для нового Today:

- импульсы группируются по сфере и имеют явный CTA;
- тап открывает модальный разбор без перестройки desktop-layout;
- пик и границы окна всегда показываются с календарной датой;
- активность сферы видна текстом, а не только точкой;
- названия техник «профекция», «соляр», «фирдар» сохраняются и получают короткие детерминированные пояснения: что это, как влияет сейчас, что можно заметить;
- внутренние термины реализации (snapshot, LLM, Swiss Ephemeris) не занимают основной пользовательский flow;
- visual baselines не обновляются до отдельного апрува владельца.

## Пример обязательного времени

Для расчёта на 1 августа с окном 31 июля 20:23 — 2 августа 02:34:

```text
пик 1 августа, 11:34
окно: с 31 июля, 20:23 до 2 августа, 02:34
```

Дата берётся из абсолютного backend-времени и форматируется в `payload.timezone`.
Frontend не восстанавливает дату сравнением строк часов.

## Волны

1. `01_BACKEND_DATE_AWARE_EVENT_TIME_TZ.md` — аддитивный wire-контракт абсолютного времени.
2. `02_FRONTEND_IMPULSE_MODAL_TZ.md` — группировка импульсов и продуктовая модалка.
3. `03_PERIOD_TECHNIQUE_EXPLANATIONS_TZ.md` — короткие пояснения профекции, соляра и фирдара в модалке и сфере.
4. `04_COMPACT_TODAY_AND_ACTIVE_SPHERES_TZ.md` — видимые active-sphere labels, полезный disclosure и компактный desktop.
5. После ревью: fixture/real-data visual acceptance без обновления baseline до апрува.

## Общие инварианты

- Новый Today сохраняет публичные `data-testid` и state attributes из AGENTS.md.
- Для старых payload/fixture без абсолютных полей сохраняется безопасный clock-only fallback, но актуальная API-проекция exact-событий обязана отдавать абсолютные поля.
- Детерминированные факты видны даже при `contentState=unavailable`; unavailable не маскируется придуманным текстом.
- Модалка использует текущий `/api/spheres/{sphere}` и не создаёт второй источник астрологических фактов.
- Никаких baseline PNG в этом изменении до апрува владельца.

## Pre-mortem: REVISE, учтено

- Контракт меняется только аддитивно и регенерируется канонической командой.
- Strict-schema и generated artifacts проверяются вместе.
- Старые fixture остаются читаемыми через fallback.
- Backend и frontend имеют отдельные write scopes; интеграция и полный diff-review выполняются архитектором.
