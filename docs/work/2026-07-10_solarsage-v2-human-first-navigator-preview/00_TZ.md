## 1. Цель

Реализовать утверждённый human-first вариант интерфейса Today V2 по трём визуальным референсам:

1. `/opt/solarsage-astro/artifacts/design/2026-07-10-v2-personal-day/01-personal-story-and-12-spheres.png`
2. `/opt/solarsage-astro/artifacts/design/2026-07-10-v2-personal-day/02-work-sphere-expanded.png`
3. `/opt/solarsage-astro/artifacts/design/2026-07-10-v2-personal-day/03-why-and-astrology-expanded.png`

Это должен быть рабочий фронтенд на реальном контракте Today V2, а не статичная картинка.

Основной продуктовый принцип:

- обычный пользователь не обязан знать, что такое транзит, профекция, фирдар, орб или аспект;
- верх экрана сначала объясняет личный сюжет дня языком жизненных ситуаций;
- все 12 сфер остаются на экране и работают как быстрый навигатор;
- астрологическая техническая основа находится только во вложенном блоке `Астрологический расчёт` внутри `Почему именно у меня`;
- V2 остаётся источником персональной точности, но техническая структура раскрывается прогрессивно.

## 5. Неизменные архитектурные правила

1. Никакой клиентской астрологии, пересчёта score, convergence, importance или выбора прогноза.
2. Источники истины только backend-owned поля `payload.v2`, `payload.concreteAdvice`, `payload.daySummary` и существующий headline payload при явно переданном prop.
3. Не выдумывать персональные факты.
4. Generic presentation copy разрешён только как детерминированное отображение backend enum, например `verdict=caution` → фиксированная human-фраза.
5. Production runtime не импортирует `lib/mocks/*`, `lib/demo-data.ts`, visual fixtures или test harness.
6. Не показывать пользователю raw `evidence`, `debug`, `strength`, activation IDs, `sourceFrame`, `targetFrame`, snake_case или английский технический dump.
7. Сохранить публичные корневые selectors:
   - `today-screen`
   - `day-summary-card`
   - `activation-evidence-card`
   - `concrete-day-advice`
   - `why-expanded`
8. Старые selectors переименовывать только вместе с обновлением всех unit/e2e tests и объяснением migration reason в отчёте.
9. Все существенно изменённые файлы должны соблюдать GRACE contract из `AGENTS.md`: `AI_HEADER`, `START_MODULE_CONTRACT`, `START_MODULE_MAP`, а для нетривиальных публичных helpers — function contracts/blocks.
10. Не выполнять форматный churn вне файлов задачи.
11. Использовать существующую тему, типографику, Tailwind и `lucide-react` через `lib/icons.ts`.
12. Не добавлять новый UI framework, новую runtime dependency или bitmap assets в product runtime.
13. UI обязан работать на ширине `390px` без горизонтального overflow.
14. Touch targets интерактивных элементов должны быть примерно `44px` или больше.
15. Enter и Space должны активировать настоящие buttons без двойного toggle.
16. Все focus states должны быть визуально различимы.
17. Light и dark theme не должны иметь нечитаемый текст или исчезающие borders/statuses.

### 11.3. Selection технических строк

Источник только:

- `v2.activationEvidence`;
- primary `v2.activationSummary.topActivatedTargets[0]`;
- порядок `primary.activationIds`.

Алгоритм:

1. построить ordered evidence по `primary.activationIds`;
2. fallback — active evidence в backend order;
3. выбрать максимум два active evidence с `kind=aspect`;
4. затем найти active non-aspect period evidence;
5. дедуплицировать их technique labels;
6. если period techniques существуют, добавить одну агрегированную строку `Долгий личный фон`;
7. итог — максимум три visual rows.

Для aspect row:

- human title через `formatActivationEvidenceTitle`;
- orb через `formatOrb`;
- phase через `getPhaseLabelRu`;
- technique label показывать только если это улучшает техническое объяснение и не дублирует heading.

Для grouped period row:

```text
Долгий личный фон
Профекция · Фирдар
```

Фактические labels должны строиться через существующий technique mapping и dedupe, а не быть захардкожены под fixture.

### 11.4. Technical row contract

```text
data-testid="astrology-calculation-item"
data-polarity={evidence.polarity}
```

Для grouped period row использовать безопасный `data-polarity`, например `neutral`, если нет единственного backend polarity.

Не показывать:

- raw evidence;
- debug;
- strength;
- IDs;
- source/target frame dump.
