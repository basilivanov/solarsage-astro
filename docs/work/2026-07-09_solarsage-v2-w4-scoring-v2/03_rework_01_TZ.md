## Required Fixes

### 1. Make V2 base scores identical to V1 pre-convergence/pre-cap sphere formula

File:

```text
apps/api/app/services/scoring_v2_service.py
```

Replace the duplicated `_compute_v1_base_scores()` formula with a call to:

```python
ScoringService()._calculate_sphere_scores(day_signals)
```

That helper is explicitly allowed by the original W4 TZ. Do not call `ScoringService.score_day()` for base scores because it includes V1 convergence/cap.

Add a regression test proving V2 base scores match `ScoringService()._calculate_sphere_scores()` for at least one fixture that exercises V1 benefic/malefic modifier logic, for example:

```text
Transit_Mercury square Venus
```

The test must fail against the current implementation, where V1 gives `1.05` and V2 base gives `0.85` for `thinking_speech_learning`.

### 2. Ignore inactive activations everywhere in V2 scoring

File:

```text
apps/api/app/services/scoring_v2_service.py
```

Only `ActivationEvidence.active is True` activations may contribute to:

- sphere activation score;
- activated family set;
- convergence bonus;
- day status activation support/tension;
- `top_activations`;
- activation-derived debug evidence where relevant.

Inactive activations can remain present in the input layer and index maps, but they must have zero scoring/status effect.

Add a regression test with an inactive Mercury activation:

```text
active=false
target_type=planet
target_key=MERCURY
strength=1.0
polarity=supportive
```

Expected:

```text
thinking_speech_learning.activation_score == 0
status_breakdown.activation_support_score == 0
status_breakdown.activation_tension_score == 0
no activation contribution for that activation id
```

### 3. Apply V1 aspect threshold in V2 day status breakdown

File:

```text
apps/api/app/services/scoring_v2_service.py
```

In `_compute_day_status_v2()`, aspect status scoring must mirror V1 threshold behavior:

```python
aw = _aspect_weight(s.aspect_type or "")
threshold = _aspect_threshold(_is_major(s.aspect_type or ""))
base = aw * s.strength
if base < threshold:
    continue
```

Then route positive/negative/conjunction scores as W4 describes.

Add a regression test with several weak positive aspects that are individually below threshold. Expected:

```text
positive_aspect_score == 0
negative_aspect_score == 0
day_status == "steady"
```

The current implementation incorrectly accumulates those weak aspects and can return `supportive`.
