## Base Score

Base score is the current signal-derived sphere score before activation bonus.

Implementation requirement:
- Use the current V1 sphere scoring formula without V1 convergence or V1 cap.
- Do not call `ScoringService.score_day()` because it applies V1 convergence/cap.
- Acceptable: instantiate `ScoringService` and call its existing `_calculate_sphere_scores(day_signals)` private helper to avoid duplicating V1 formula.
- Do not change `ScoringService` behavior.

For each sphere:

```text
base_score = v1_signal_sphere_score_before_activation_bonus
```

Add one `SphereContribution` when `base_score != 0`:

```text
source = "base_signal"
source_id = "base_signal:<sphere_key>"
amount = base_score
evidence = "Base day signal score for <sphere title>"
```

## Activation Contribution

For each active activation, map it to zero or more spheres.

### Mapping activation targets to spheres

Planet target:

```text
activation.target_type == "planet"
target_key = activation.target_key.upper()
sphere matches if target_key in spheres.<sphere>.planets
target_weight = spheres.<sphere>.planets[target_key]
```

House target:

```text
activation.target_type == "house"
house = activation.house or int(activation.target_key)
sphere matches if house in spheres.<sphere>.houses
target_weight = scoring_v2.target_weight_defaults.house
```

Lot target:

```text
activation.target_type == "lot"
target_key = activation.target_key.upper()
sphere matches if target_key in spheres.<sphere>.lots
target_weight = scoring_v2.target_weight_defaults.lot
```

Angle target:

```text
activation.target_type == "angle"
angle = activation.angle or activation.target_key.upper()
sphere matches from scoring_v2.angle_sphere_map[angle]
target_weight = scoring_v2.target_weight_defaults.angle
```

Sphere target:

```text
activation.target_type == "sphere"
sphere matches activation.target_key
target_weight = scoring_v2.target_weight_defaults.sphere
```

If an activation maps to no sphere, it remains in `debug.unmapped_activations` but contributes zero.

### Contribution formula

For every activation-sphere match:

```text
amount = activation.strength
  * technique_family_weight
  * target_weight
  * polarity_sphere_amount_modifier
```

Where:
- `technique_family_weight` is `activation_rules.technique_families[family].independence_weight`;
- `family` is `activation.technique_family` if present, else derived from `activation.technique` through `activation_rules.technique_families`;
- `polarity_sphere_amount_modifier` comes from `scoring_v2.activation_polarity.sphere_amount_modifier[activation.polarity]`.

Round contribution amounts to 4 decimals in output.

Add `SphereContribution`:

```text
source = "activation"
source_id = activation.id
amount = rounded amount
before = score before this contribution
after = score after this contribution
evidence = activation.evidence
```

Do not drop tense activations. Tense activations still add sphere salience; they affect day tension through the status breakdown.

## Convergence Bonus

For each sphere:

```python
activated_families = set()
for activation mapped to sphere:
    activated_families.add(family)
n = len(activated_families)
bonus = convergence_curve[n capped at 5] * sphere_convergence_weight
```

Requirements:
- Deduplicate by activation id before counting.
- Annual and monthly profection both count as one `profection` family.
- Solar return and lunar return both count as one `return` family.
- Solar arc and secondary progression both count as one `progression` family.
- Multiple transit aspects count as one `transit` family.
- `eclipse_window` counts as one `eclipse` family.

Add contribution only when `bonus > 0`:

```text
source = "convergence"
source_id = "convergence:<sphere_key>"
amount = bonus
before = base_score + activation_score
after = before + bonus
evidence = "Convergence bonus: <n> independent technique families (<family list>)"
```

Store family lists in `debug.convergence_by_sphere`.

## Anti-Dominance

After base + activation + convergence:

```text
raw_score = base_score + activation_score + convergence_bonus
sum_all_positive_scores = sum(raw_score for raw_score > 0)
cap_value = dominance_cap.threshold * sum_all_positive_scores
```

If:

```text
raw_score > cap_value
```

then:

```text
final_score = cap_value
dominance_capped = true
cap_amount = final_score - raw_score
```

Add contribution:

```text
source = "cap"
source_id = "cap:<sphere_key>"
amount = cap_amount  # negative
before = raw_score
after = final_score
evidence = "Dominance cap applied: sphere exceeded 65% of total salience"
```

If cap disabled in canon, do not cap and set `dominance_capped=false`.

## Day Status V2

Compute transparent status breakdown.

Base aspect scores from `day_signals`:
- Use same aspect weights and thresholds as V1.
- `trine`/`sextile` add to `positive_aspect_score`.
- `square`/`opposition` add to `negative_aspect_score`.
- `conjunction` and other aspects split 50/50.

Activation status scores from `activation_layer.activations`:

```text
activation_status_amount = activation.strength * technique_family_weight
activation_support_score += activation_status_amount * status_support_modifier[polarity]
activation_tension_score += activation_status_amount * status_tension_modifier[polarity]
```

Then:

```text
support_score = positive_aspect_score + activation_support_score
tension_score = negative_aspect_score + activation_tension_score
```

Status:

```text
supportive if support_score > tension_score * positive_ratio and support_score >= positive_min_score
tense      if tension_score > support_score * negative_ratio and tension_score >= negative_min_score
steady     otherwise
```

`status_breakdown` must include at least:

```json
{
  "positive_aspect_score": 0.0,
  "negative_aspect_score": 0.0,
  "activation_support_score": 0.0,
  "activation_tension_score": 0.0,
  "support_score": 0.0,
  "tension_score": 0.0,
  "ratio": null,
  "rule": "supportive_if_support_score_gt_tension_1_3"
}
```

Use `ratio = support_score / tension_score` rounded to 4 decimals when `tension_score > 0`; otherwise `null`.

Do not let activation layer flip status without these visible fields.
