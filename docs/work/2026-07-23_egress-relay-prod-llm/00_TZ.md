# ТЗ — Egress-relay на dev-хосте для прода (LLM + Telegram API)

Дата: 2026-07-23
Исполнитель: кодер в tmux astro2
Архитектор: ревью + rollout (правки на проде и запуск relay делает НЕ кодер)

## 1. Контекст

Прод `astro.vasiliy-ivanov.ru` (157.22.192.242) живёт на хостере, где:

- `openrouter.ai` → 403 (geo-block), `api.telegram.org` → TCP timeout. LLM полностью мёртв, данные в приложении не генерируются.
- Dev-хост (эта машина, `45.88.172.246`, Амстердам) имеет нормальный egress к обоим.

Решение (согласовано): **TCP forwarder на dev + hosts-override на проде**.
На dev поднимаем nginx stream (ssl_preread): читает SNI, проксирует сырой TCP на настоящий сервер. TLS терминируется на настоящем сервере, сертификаты валидны, код приложения НЕ меняется.
На проде api-контейнер получает `extra_hosts`: `openrouter.ai` / `api.telegram.org` → IP dev-хоста, и `OPENROUTER_BASE_URL` с портом relay (это делает архитектор при rollout, НЕ кодер).

Порт relay: **8443** (на dev свободен, `ss -tlnp | grep 8443` пусто; в UFW уже есть разрешение 8443 — сужение до IP прода сделает архитектор при rollout).

Почему не 443 на dev: там хостовой nginx с десятком чужих сайтов (magia и пр.) — не трогаем.

## 2. Файлы для создания/правки

### 2.1 Создать `infra/relay/docker-compose.yml`

```yaml
# Egress relay for production (see README.md in this directory).
services:
  egress-relay:
    image: nginx:1.27-alpine
    container_name: egress-relay
    restart: unless-stopped
    ports:
      - "8443:8443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
```

Без `version:`-ключа (deprecated). Без networks — default сети достаточно; source IP клиента при published port сохраняется (DNAT), это важно для allow/deny.

### 2.2 Создать `infra/relay/nginx.conf`

Полная замена nginx.conf (в образе nginx:alpine дефолтный конфиг содержит только http-блок, поэтому монтируем целиком):

```nginx
user  nginx;
worker_processes  auto;
error_log  /var/log/nginx/error.log warn;
pid        /var/run/nginx.pid;

events { worker_connections  1024; }

stream {
    log_format relay '$remote_addr [$time_local] SNI=$ssl_preread_server_name -> $upstream_addr ($status)';
    access_log /var/log/nginx/access.log relay;

    resolver 1.1.1.1 8.8.8.8 valid=300s ipv6=off;
    resolver_timeout 5s;

    # Whitelist: only these SNI names are relayed, to their real servers.
    # Unknown SNI -> 127.0.0.1:9 (connection refused, client reset).
    # ВАЖНО: stream-модуль НЕ поддерживает `if`/`return` — reject только через map на мёртвый адрес.
    map $ssl_preread_server_name $relay_upstream {
        api.telegram.org  api.telegram.org:443;
        openrouter.ai     openrouter.ai:443;
        default           127.0.0.1:9;
    }

    server {
        listen 8443;

        # Only the production host may use this relay.
        allow 157.22.192.242;
        deny   all;

        ssl_preread on;
        proxy_pass $relay_upstream;
        proxy_connect_timeout 10s;
        proxy_timeout 300s;
    }
}
```

Проверка конфигурации (кодер выполняет, образ скачается с Docker Hub):
`docker run --rm -v "$PWD/infra/relay/nginx.conf:/etc/nginx/nginx.conf:ro" nginx:1.27-alpine nginx -t`
Должно быть `syntax is ok` / `test is successful`.

### 2.3 Правка `infra/production/docker-compose.app.yml`

В сервис `api` добавить (рядом с прочими его ключами, сохранить стиль файла):

```yaml
    extra_hosts:
      # Egress relay on dev host (Amsterdam) — see infra/relay/README.md.
      # openrouter.ai / api.telegram.org are unreachable from the prod hoster.
      - "api.telegram.org:45.88.172.246"
      - "openrouter.ai:45.88.172.246"
```

Перед правкой прочитать файл целиком: не сломать digest-pinning, healthcheck, depends_on. Менять ТОЛЬКО сервис `api`. sidecar/frontend НЕ трогать.

### 2.4 Создать `infra/relay/README.md`

Коротко (10-20 строк), на русском: что это (TCP egress relay для прода), почему (geo-block openrouter + timeout telegram с хостера прода), как устроено (SNI whitelist, allow только IP прода, TLS end-to-end), как эксплуатировать (`docker compose -f infra/relay/docker-compose.yml up -d` на dev-хосте), как проверить (curl-команда из раздела 3). Указать, что прод-side настройка (extra_hosts в installed compose + `OPENROUTER_BASE_URL=https://openrouter.ai:8443/api/v1` в `/etc/solarsage/app.env`) выполняется архитектором при rollout.

### 2.5 Правка `AGENTS.md`

В секцию `## Production host (astro.vasiliy-ivanov.ru)` после egress-матрицы добавить 2-3 строки: на dev-хосте `45.88.172.246:8443` работает egress-relay (`infra/relay/`, контейнер `egress-relay`), через который прод ходит к `openrouter.ai` (и опционально `api.telegram.org`); на проде это прозрачно через `extra_hosts` + `OPENROUTER_BASE_URL` с портом 8443.

## 3. Критерии приёмки

1. `docker run --rm -v .../nginx.conf:/etc/nginx/nginx.conf:ro nginx:1.27-alpine nginx -t` → успех (кодер выполняет и показывает вывод).
2. `git diff` содержит только: новый `infra/relay/` (3 файла), правка `infra/production/docker-compose.app.yml` (только extra_hosts в api), правка `AGENTS.md` (2-3 строки).
3. В ТЗ-отчёте кодер указывает, что НЕ трогал: prod, `/etc/solarsage/*`, UFW, app.env, хостовой nginx dev.

## 4. Ограничения

- **Ничего не коммитить** — коммит делает ревьюер.
- Не запускать relay на dev (это rollout, делает архитектор). Только `nginx -t` через временный контейнер.
- Не трогать `/etc/nginx/*`, UFW, любые файлы на проде, секреты.
- Без оверинжениринга: не добавлять http-блок, healthchecks, метрики, reload-скрипты, отдельные networks. Ровно 3 новых файла + 2 правки.

## 5. Подводные камни (на что обратить внимание)

- stream-модуль НЕ имеет `if`/`return` — reject неизвестного SNI только через `map ... default 127.0.0.1:9`.
- `proxy_pass` с переменной требует `resolver` — иначе nginx не стартует.
- В `docker-compose.yml` не добавлять `version:` (deprecated warning).
- В `infra/production/docker-compose.app.yml` образы pinned по digest — не переписывать строки image, добавить только extra_hosts.
- YAML-отступы в compose: extra_hosts — ключ сервиса `api`, не верхнего уровня.
- После `nginx -t` временный контейнер должен быть удалён (флаг `--rm` в команде выше уже это гарантирует).
