# narrative-model-eval-v1 — Today narrative v5

Immutable local evaluation task for five OpenRouter models on real Today
Convergence inputs collected for the owner profile. The task date is
2026-08-09; the candidate window is 2026-08-09 through 2026-09-25.

The source snapshot is pinned by `base_sha` and `tree_sha` in `models.toml`.

## Inputs

`inputs.json` is generated by the free `validate` command from the dev
PostgreSQL profile `eb3876be-e1b4-43d6-b887-1f8554e33150`. It runs the existing
deterministic calculation and snapshot builder in memory, then builds the v5
prompt with `TodayNarrativePerson`. It selects up to 14 dates by coverage:
at least three convergence days, three quiet days, every available public
polarity, eight facets, and both hero and medium convergence evidence where
the source window provides them. The committed prompt masks the owner's name
as `ИМЯ`; no canonical profile payload or raw provider output is committed.
If the real source window cannot satisfy a target, `validate` reports the
coverage gap and does not permit a paid run; it never fabricates a day.

The input record stores only the safe prompt, deterministic presentation
metadata, expected block IDs/evidence IDs, `input_hash`, and coverage fields.
After a scored run, `inputs.json` is immutable. Raw full prompts/responses stay
under the gitignored `.eval-runs/` directory.

## Arm A — production JSON object

The request body is the production OpenRouter body, byte-for-byte except for
`model`:

```json
{
  "model": "<model>",
  "messages": [{"role": "user", "content": "<v5 prompt>"}],
  "max_tokens": 2000,
  "response_format": {"type": "json_object"}
}
```

No temperature is sent. The response uses the current keyed template:

```json
{
  "convergences": {"cvg_…": {"summary": {}, "meaning": {}, "action": {}}},
  "main_event": {"summary": {}, "meaning": {}, "action": {}} | null,
  "impulses": {"evt_…": {"summary": {}, "meaning": {}, "action": {}}}
}
```

## Arm B — strict JSON Schema

Arm B keeps the same user input and rules but replaces the final template
section with arrays. The request adds the provider requirement:

```json
{
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "today_narrative",
      "strict": true,
      "schema": "<the schema below>"
    }
  },
  "provider": {"require_parameters": true}
}
```

The schema deliberately uses arrays because strict structured outputs cannot
express dictionaries with arbitrary dynamic keys:

```json
{
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "convergences": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "properties": {
          "groupId": {"type": "string"},
          "summary": {"$ref": "#/$defs/claim"},
          "meaning": {"$ref": "#/$defs/claim"},
          "action": {"$ref": "#/$defs/claim"}
        },
        "required": ["groupId", "summary", "meaning", "action"]
      }
    },
    "main_event": {"anyOf": [{"$ref": "#/$defs/block"}, {"type": "null"}]},
    "impulses": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "properties": {
          "eventId": {"type": "string"},
          "summary": {"$ref": "#/$defs/claim"},
          "meaning": {"$ref": "#/$defs/claim"},
          "action": {"$ref": "#/$defs/claim"}
        },
        "required": ["eventId", "summary", "meaning", "action"]
      }
    }
  },
  "required": ["convergences", "main_event", "impulses"],
  "$defs": {
    "claim": {
      "anyOf": [
        {"type": "null"},
        {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "text": {"type": "string"},
            "sourceEventIds": {"type": "array", "items": {"type": "string"}}
          },
          "required": ["text", "sourceEventIds"]
        }
      ]
    },
    "block": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "summary": {"$ref": "#/$defs/claim"},
        "meaning": {"$ref": "#/$defs/claim"},
        "action": {"$ref": "#/$defs/claim"}
      },
      "required": ["summary", "meaning", "action"]
    }
  }
}
```

HTTP 400/404 for the strict declaration is recorded as
`strict_unsupported` without retry. Transport and 5xx errors receive one
retry. All other response scoring is shared after B is normalized back to
the keyed shape.

## Execution matrix and budget

Five models × two arms × two repeats × up to fourteen inputs = 280 calls.
Concurrency is 2 and timeout is 60 seconds. The hard cumulative budget guard
is `$0.90`; the expected usage-based estimate is printed by `validate` and
must remain at or below `$0.60`. A paid call is legal only after the reviewer
explicitly invokes `run --confirm-paid-run`. `--selftest` and `validate` never
make OpenRouter calls.

## Model snapshot

The exact five model IDs and immutable prices live in `models.toml` and
`pricing-2026-08-09.toml`. No API key or provider configuration is copied into
the task. Each model may override `max_tokens` (default 2000); the two
DeepSeek V4 entries use 6000 to leave room for reasoning plus visible JSON.
Optional `extra_body` values are copied to the top level of that model's
request after validation.

The raw response artifact preserves the complete provider `usage` object,
including nested `completion_tokens_details.reasoning_tokens`, while keeping
the normalized top-level `prompt_tokens` and `completion_tokens` fields for
scoring compatibility. A response with `completion_tokens >= max_tokens` is
marked `truncated` and contributes to `truncated_rate`; it is excluded from
content metrics.

The paid runner accepts `--models key1,key2` and `--out-dir
.eval-runs/narrative-model-eval-v1/<run-id>`. The latter merges selected model
files into an existing raw run, overwriting only those model files and
preserving the other models' files.

The report's monthly projection assumes 100 DAU × 30 days = 3000 measured
narrative calls per month.

## Commands

```bash
python3 scripts/narrative_model_eval.py --selftest
python3 scripts/narrative_model_eval.py validate --task evals/tasks/today-narrative-v5-models
python3 scripts/narrative_model_eval.py validate --task evals/tasks/today-narrative-v5-models \
  --models deepseek-v4-flash,deepseek-v4-pro
python3 scripts/narrative_model_eval.py run --task evals/tasks/today-narrative-v5-models --confirm-paid-run
python3 scripts/narrative_model_eval.py run --task evals/tasks/today-narrative-v5-models \
  --models deepseek-v4-flash,deepseek-v4-pro \
  --out-dir .eval-runs/narrative-model-eval-v1/<run-id> --confirm-paid-run
python3 scripts/narrative_eval_report.py --run evals/results/<run-id>
```
